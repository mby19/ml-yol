Anlatım01 / 12

Altyapı kod olarak: arzu edilen durum ve onu koruyan döngü

Faz 4'te Docker ve Kubernetes gördün: konteyner, dağıtım, ölçekleme. Orada "neyi çalıştıracağın" vardı; burada "neyin var olduğunu nasıl garanti edersin" var. Altyapı kod olarak (infrastructure as code, IaC) tam olarak bu soruyu cevaplar.

Bildirimsel (declarative) düşünmek

İki yaklaşım var:

  • Emir kipinde (imperative): "kova oluştur, sonra IAM rolü oluştur, sonra rollere izin ver, sonra uç noktayı aç." Bash betiği budur. İki kez çalıştırırsan ya hata alırsın ya iki tane kova olur. Yarım kalırsa ne olduğunu kimse bilmez.
  • Bildirimsel: "Şu kaynaklar şu özelliklerle var olsun." Araç, mevcut durumla arzuyu karşılaştırıp farkı uygular.

Terraform'un çekirdek döngüsü dört parçadır:

  1. Yapılandırma (HCL): arzu edilen kaynaklar.
  2. Durum dosyası (state): aracın bildiği mevcut durum — kaynak kimlikleri ve özellikleri. Bu dosya olmadan araç "benim oluşturduğum kova" ile "elle açılmış kova"yı ayırt edemez.
  3. Plan: fark. + ekle, ~ yerinde güncelle, -/+ sil ve yeniden yarat, - sil.
  4. Uygula (plan/apply): bağımlılık sırasına göre uygula; sonucu duruma yaz.

Durum dosyası iki şeyi bedava getirir: idempotanlık (ikinci kez uygula → hiçbir şey olmaz) ve kayma tespiti (biri konsoldan bir şey değiştirdiyse plan bunu gösterir).

Değişmez kaynak: ~ mi -/+ mı

Bazı alanlar değiştirilemez: bir kovanın bölgesi, bir GPU örneğinin tipi. Bu alanlar değişince araç kaynağı siler ve yeniden yaratır (değişmez kaynak). Plan çıktısındaki -/+ işareti bunu söyler ve bu, IaC'nin en tehlikeli anıdır: "sadece bölge değiştirdim" derken veri kovanı silinir.

Koruma araçları:

  • lifecycle { prevent_destroy = true } — kazara silmeyi ve değişmez alan değişiminden doğan yeniden yaratmayı (replace) engeller.
  • deletion_protection — sağlayıcı tarafında.
  • Silme planı için ayrı bir onay adımı (CI'da plan çıktısını insan onayına sunmak).

Uzak durum ve kilitleme

Durum dosyası tek doğruluk kaynağıdır; iki mühendis aynı anda uygularsa ikisi de aynı durumu yazar → kaynaklar birbirine karışır. Çözüm:

  • Uzak durum: S3/GCS üzerinde tek kopya.
  • Kilitleme: uygulama sırasında kilit; ikinci uygulama bekler. (Terraform'da S3 + DynamoDB veya S3 native locking; OpenTofu ve Terraform Cloud'da farklı mekanizmalar.)
  • Şifreleme ve erişim: durum dosyası sırların düz metin kopyalarını taşıyabilir; kovayı herkese açık yapmak, sırları yayınlamak demektir.
# PC'de çalıştır — Terraform veya OpenTofu kurulumu gerekir (brew install opentofu).
terraform {
  required_version = ">= 1.10"   # use_lockfile 1.10 ile geldi
  backend "s3" {                       # uzak durum
    bucket         = "sirket-tf-state"
    key            = "ml/prod/terraform.tfstate"
    region         = "eu-central-1"
    use_lockfile   = true               # S3 native kilitleme (DynamoDB'siz)
    encrypt        = true
  }
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 6.0" }
  }
}

variable "ortam" { default = "prod" }

resource "aws_s3_bucket" "model" {
  bucket = "ml-model-${var.ortam}"
  lifecycle { prevent_destroy = true }   # kazara silme yok
}

output "model_kovasi" { value = aws_s3_bucket.model.bucket }

Modüller ve ortamlar

Aynı yapılandırmayı üç ortamda kullanmak istiyorsun. İki yol:

  • Modül + farklı değişkenler: bir modül (ör. modules/ml_platform), üç kök yapılandırma (envs/dev, envs/staging, envs/prod) onu farklı değişkenlerle çağırır.
  • Workspace: aynı kod, farklı durum dosyası. Küçük farklılıklar için pratik; ama ortamlar arasında fark büyüdükçe if yığınına dönüşür.

Kural: ortamlar arasındaki fark yalnızca değişken olmalı, kod yolu olmamalı. Aksi hâlde "prod'da çalışıyor, dev'de çalışmıyor" hataları altyapı katmanına taşınır.

ML'in IaC'ye eklediği üç şey

  1. Kota. GPU kotası, bölge başına ayrı ve varsayılan olarak sıfır olabilir. apply kotayı açmaz; kota artırımı ayrı bir insan sürecidir. Bu yüzden plan "başarılı" görünüp uygulama yarı yolda kalabilir — IaC'nin en sık sürprizi.
  2. Model sürümü bir değişkendir. Uç nokta tanımında model_version = "v42" gibi bir değişken olmalı; aksi hâlde "hangi model yayında" sorusu altyapı kodundan cevaplanamaz. Model kaydı ile IaC birbirine bağlanır.
  3. Sırlar ve veri. Eğitim verisi kovası, erişim politikaları, KMS anahtarları. IaC bunları kurar; ama veri IaC'ye girmez. Veri sürümü ayrı bir sistemin (göl evi dersindeki tablo sürümleri) işi.

Bulut ML servisleri: ne satın alıyorsun, neyi kaybediyorsun (devam)

Ölçüm (gerçek LightGBM modeli, 120 ağaç, bu makinede): tek istek p50 ≈ 0,4 ms (koşular arası 0,36–0,52), p99 ≈ 0,6–1,3 ms; toplu çıkarımda istek başına süre batch 1'de ~0,4 ms, batch 64'te ~0,006 ms. Tek çekirdek, batch 16 ile 26.000–42.000 istek/sn yapıyor.

Sonuç: 500 istek/sn hedefi için 1 çekirdek yeterli. Yani bu iş yükünde bulut maliyeti hesaplama değil, kullanılabilirlik ve yedeklilik tarafından belirleniyor: iki bölge, iki kopya, yükleme testi.

Karşılaştırma için aynı formülü farklı hizmet süreleriyle çalıştırdık (%90 doluluk):

senaryo hizmet süresi paralel birim kuyruk gecikmesi
ölçülen tablo modeli 0,4 ms 1 3,3 ms
küçük CNN 20 ms 12 180 ms
LLM (7B, 512 token) 200 ms 112 1800 ms

Üç satır, bulut mimarisinin neden model türüne göre değiştiğini gösteriyor: aynı 500 istek/sn, birinde tek çekirdek, diğerinde 112 paralel birim. Ve dikkat: %90 doluluğun bedeli hizmet süresinin 9 katı kuyruk. Bu yüzden üretimde doluluk hedefi %50-70 tutulur — pahalı görünür, ama kuyruk gecikmesi doğrusal değil hiperbolik büyür (Faz 4'teki kuyruk dersinin kapasite karşılığı).

ppp saatlik birim fiyatı. Fiyatları buraya yazmıyoruz çünkü sürekli değişir; sağlayıcının fiyat sayfasından al ve formüle koy. Ölçtüğümüz 1 çekirdekli senaryo için 0,10 / 0,20 / 0,40 /saatvarsayımlarıaylık73/146/292/saat varsayımları aylık 73 / 146 / 292 /saatvarsayımlarıaylık73/146/292 veriyor — yani bu iş yükünde doğru soru "hangi örnek tipi" değil, "kaç kopya ve hangi SLA".

Toplu çıkarım genelde 3-10 kat daha ucuzdur: aynı donanımı saatlerce dolu tutarsın, istek başına kuyruk beklemezsin. Gece çalışan skorlama işini gerçek zamanlı uç noktaya koymak, en yaygın bulut israfıdır.

Kod06 / 12

Terraform'un çekirdek döngüsünü sıfırdan: plan, bağımlılık sırası, idempotanlık, kayma, değişmez kaynak.

# PC'de çalıştır — gerekli: yalnızca Python standart kütüphanesi
# Arzu edilen durum + mevcut durum -> plan -> uygula. Terraform'un çekirdek döngüsü.
import copy

IMMUTABLE = {"bucket_adi", "bolge"}          # değişirse kaynak yeniden yaratılır (-/+)

def kaynaklar(ortam):
    """for_each: aynı tanım, üç ortam. Ad çakışması üretimde en sık hata."""
    return {
      f"veri_{ortam}":  {"tip": "bucket", "spec": {"bucket_adi": f"ml-veri-{ortam}", "bolge": "eu-central-1"},
                          "koruma": True},
      f"model_{ortam}": {"tip": "bucket", "spec": {"bucket_adi": f"ml-model-{ortam}", "bolge": "eu-central-1"},
                          "koruma": True},
      f"tablo_{ortam}": {"tip": "tablo", "spec": {"ad": "trip_features", "saklama_gun": 30},
                          "bagimli": [f"veri_{ortam}"]},
      f"egitim_{ortam}": {"tip": "is", "spec": {"komut": "train.py", "gpu": "A10G", "adet": 1},
                          "bagimli": [f"tablo_{ortam}", f"model_{ortam}"]},
      f"uc_{ortam}":    {"tip": "endpoint", "spec": {"model": "v3", "ornek": "g5.xlarge", "adet": 2},
                          "bagimli": [f"model_{ortam}"]},
    }

ARZU = {}
for ortam in ("deneme", "uretim"):            # for_each = ["deneme", "uretim"]
    ARZU.update(kaynaklar(ortam))

def plan(arzu, mevcut):
    adimlar = []
    for ad, r in arzu.items():
        if ad not in mevcut:
            adimlar.append(("ekle", ad))
        elif mevcut[ad]["spec"] != r["spec"]:
            degisen = {k for k in r["spec"] if r["spec"][k] != mevcut[ad]["spec"].get(k)}
            if degisen & IMMUTABLE:
                korumali = r.get("koruma") or mevcut[ad].get("koruma")
                adimlar.append(("degistir(engelli)" if korumali else "degistir", ad))
            else:
                adimlar.append(("guncelle", ad))
    for ad in mevcut:
        if ad not in arzu:
            adimlar.append(("sil(engelli)" if mevcut[ad].get("koruma") else "sil", ad))
    return adimlar

def sirala(arzu):
    kalan, sira, gorulen = list(arzu), [], set()
    while kalan:
        ilerleme = False
        for ad in list(kalan):
            if all(b in gorulen for b in arzu[ad].get("bagimli", [])):
                sira.append(ad); gorulen.add(ad); kalan.remove(ad); ilerleme = True
        if not ilerleme:
            raise ValueError(f"döngüsel bağımlılık: {kalan}")
    return sira

def uygula(arzu, mevcut, adimlar):
    for eylem, ad in adimlar:
        if eylem in ("ekle", "degistir"):
            mevcut[ad] = {"spec": copy.deepcopy(arzu[ad]["spec"]), "koruma": arzu[ad].get("koruma", False),
                          "id": f"{arzu[ad]['tip']}-{abs(hash(ad)) % 10000:04d}"}
        elif eylem == "guncelle":
            mevcut[ad]["spec"] = copy.deepcopy(arzu[ad]["spec"])
        elif eylem == "sil":
            mevcut.pop(ad)
    return mevcut

MEVCUT = {}
p = plan(ARZU, MEVCUT)
print(f"1) ilk plan: {len(p)} kaynak → {dict((e, sum(1 for x in p if x[0]==e)) for e, _ in p)}")
print("   sıra:", sirala(ARZU)[:5], "...")
MEVCUT = uygula(ARZU, MEVCUT, p)
print("2) ikinci plan:", plan(ARZU, MEVCUT) or "boş — idempotent")

MEVCUT["uc_uretim"]["spec"]["adet"] = 6          # elle müdahale: kayma
print("3) kayma sonrası plan:", plan(ARZU, MEVCUT))
MEVCUT = uygula(ARZU, MEVCUT, plan(ARZU, MEVCUT))

ARZU["model_uretim"]["spec"]["bolge"] = "us-east-1"   # değişmez alan
print("4) değişmez alan değişti:", plan(ARZU, MEVCUT),
      "→ korumalı kaynak yeniden yaratılmaz; Terraform planı reddeder")
ARZU["model_uretim"]["spec"]["bolge"] = "eu-central-1"   # koruma yüzünden değişiklik geri alınır

MEVCUT = uygula(ARZU, MEVCUT, plan(ARZU, MEVCUT))

del ARZU["veri_deneme"]; del ARZU["uc_deneme"]     # deneme ortamı kaldırıldı
print("5) kaynak kaldırıldı:", plan(ARZU, MEVCUT), "→ korumalı bucket silinmiyor")
# Beklenen çıktı:
# 1) ilk plan: 10 kaynak → {'ekle': 10}
#    sıra: ['veri_deneme', 'model_deneme', 'tablo_deneme', 'egitim_deneme', 'uc_deneme'] ...
# 2) ikinci plan: boş — idempotent
# 3) kayma sonrası plan: [('guncelle', 'uc_uretim')]
# 4) değişmez alan değişti: [('degistir(engelli)', 'model_uretim')] → korumalı kaynak yeniden yaratılmaz; Terraform planı reddeder
# 5) kaynak kaldırıldı: [('sil(engelli)', 'veri_deneme'), ('sil', 'uc_deneme')] → korumalı bucket silinmiyor

Bu 30 satır, Terraform'un bütün karar mekanizması: fark hesabı, topolojik sıra, değişmezlik, koruma. Gerçek araçta üstüne sağlayıcı API'leri, uzak durum ve kilitleme eklenir; mantık aynı kalır.

Kapasite modeli: ölçülen gecikmeden örnek sayısı ve maliyet.

# test: python 3.13 · duckdb 2.0.0
# PC'de çalıştır — gerekli: duckdb, numpy, pandas, lightgbm
# Veri (48 MB):  curl -L -o yellow_2024-01.parquet \
#   https://d37ci6vzurychx.cloudfront.net/trip-data/yellow_tripdata_2024-01.parquet
# Bulut kapasite modeli: ölçülen gecikme/verimden örnek sayısı ve maliyet çıkar.
import duckdb, numpy as np, time, lightgbm as lgb

c = duckdb.connect()
df = c.sql("""SELECT trip_distance, passenger_count, fare_amount, tip_amount,
                     EXTRACT(hour FROM tpep_pickup_datetime) hr, PULocationID zone
              FROM 'yellow_2024-01.parquet'
              WHERE payment_type = 1 AND fare_amount > 2.5 AND trip_distance > 0
                AND tpep_pickup_datetime >= TIMESTAMP '2024-01-01'
                AND tpep_pickup_datetime <  TIMESTAMP '2024-01-08'""").df()
X = df[["trip_distance", "passenger_count", "fare_amount", "hr", "zone"]].astype(float).to_numpy()
y = (df.tip_amount / df.fare_amount > 0.2).to_numpy().astype(int)
m = lgb.LGBMClassifier(n_estimators=120, verbose=-1, random_state=0).fit(X, y)
print("model: 120 ağaç,", X.shape[0], "satır")

# --- 1) Tek istek gecikmesi: ortalama değil yüzdelik
gec = []
for i in range(400):
    t = time.perf_counter(); m.predict_proba(X[i:i+1]); gec.append((time.perf_counter() - t) * 1000)
gec = np.array(gec)
print(f"tek istek: p50 {np.percentile(gec,50):.2f} ms | p95 {np.percentile(gec,95):.2f} ms | "
      f"p99 {np.percentile(gec,99):.2f} ms")

# --- 2) Toplu çıkarım: verim batch ile artar, gecikme de artar
print("batch  istek/ sn   ms/istek")
for b in (1, 8, 64, 256):
    n = max(1, 2048 // b)
    t = time.perf_counter()
    for _ in range(n): m.predict_proba(X[:b])
    s = time.perf_counter() - t

Kontrol09 / 12

terraform plan çıktısında bir S3 kovası için -/+ görüyorsun, değişen tek şey region. Ne olur, nasıl engellersin?

Cevabı göster

-/+ = kaynak silinip yeniden yaratılacak. Bölge değiştirilemez bir alan olduğu için Terraform kovayı silip yeni bölgede açar; içindeki nesneler (varsa) kaybolur ve yeni kova boş olur. Engellemek için: (1) lifecycle { prevent_destroy = true } ekle — uygulama hata verir; (2) deletion_protection/sağlayıcı koruması; (3) doğru yaklaşım genelde kovayı değiştirmek değil, yeni kovayı ekleyip veriyi taşımak (iki aşamalı geçiş): önce yeni kovayı oluştur, veriyi kopyala, sonra eskiyi kontrollü sil. Planı CI'da "-/+ varsa insan onayı" kuralıyla korumak, kazayı koddan önce süreçte durdurur.

Kontrol10 / 12

Tablo modelin 500 istek/sn'yi tek çekirdekte karşılıyor. Yine de iki bölgede üç kopya çalıştırıyorsun. Bu israf mı? Savunmasını ve karşı argümanı yaz.

Cevabı göster

Savunma: hedef yalnızca verim değil SLA. Tek çekirdek tek hata noktasıdır; güncelleme, düğüm arızası veya bölge kesintisi hizmeti durdurur. Üç kopya + iki bölge, bir kopya kaybında kapasitenin %67'sini korur ve sıfır kesintiyle dağıtım sağlar. Karşı argüman: bu ölçekte gerçekten 500 istek/sn var mı, yoksa tepe değer mi? Trafik 50 istek/sn ise üç kopya gereksizdir; tek bölge + iki kopya + hızlı yeniden başlatma yeterli olabilir. Doğru cevap ölçümle verilir: p99 gecikme, hata bütçesi (SLO), ve kesinti maliyeti. Kapasite planı (term:kapasite-plani) hem verim hem yedeklilik boyutunu içermeli; yalnızca CPU kullanımına bakmak yanıltır.
