Geometry of Gradients and Gradient Descent

Consider the expression from (see equation above) again:

L(w+ϵ)≈L(w)+ϵ⋅∇wL(w).L(\mathbf{w} + \boldsymbol{\epsilon}) \approx L(\mathbf{w}) + \boldsymbol{\epsilon}\cdot \nabla_{\mathbf{w}} L(\mathbf{w}).L(w+ϵ)≈L(w)+ϵ⋅∇w​L(w).

Let's suppose that I want to use this to help minimize our loss LLL. Let's understand geometrically the algorithm of gradient descent first described in (see related section). What we will do is the following:

  1. Start with a random choice for the initial parameters w\mathbf{w}w.
  2. Find the direction v\mathbf{v}v that makes LLL decrease the most rapidly at w\mathbf{w}w.
  3. Take a small step in that direction: w→w+ϵv\mathbf{w} \rightarrow \mathbf{w} + \epsilon\mathbf{v}w→w+ϵv.
  4. Repeat.

The only thing we do not know exactly how to do is to compute the vector v\mathbf{v}v in the second step. We will call such a direction the direction of steepest descent. Using the geometric understanding of dot products from (see related section), we see that we can rewrite (see equation above) as

L(w+v)≈L(w)+v⋅∇wL(w)=L(w)+∥∇wL(w)∥cos⁡(θ).L(\mathbf{w} + \mathbf{v}) \approx L(\mathbf{w}) + \mathbf{v}\cdot \nabla_{\mathbf{w}} L(\mathbf{w}) = L(\mathbf{w}) + \|\nabla_{\mathbf{w}} L(\mathbf{w})\|\cos(\theta).L(w+v)≈L(w)+v⋅∇w​L(w)=L(w)+∥∇w​L(w)∥cos(θ).

Note that we have taken our direction to have length one for convenience, and used θ\thetaθ for the angle between v\mathbf{v}v and ∇wL(w)\nabla_{\mathbf{w}} L(\mathbf{w})∇w​L(w). If we want to find the direction that decreases LLL as rapidly as possible, we want to make this expression as negative as possible. The only way the direction we pick enters into this equation is through cos⁡(θ)\cos(\theta)cos(θ), and thus we wish to make this cosine as negative as possible. Now, recalling the shape of cosine, we can make this as negative as possible by making cos⁡(θ)=−1\cos(\theta) = -1cos(θ)=−1 or equivalently making the angle between the gradient and our chosen direction to be π\piπ radians, or equivalently 180180180 degrees. The only way to achieve this is to head in the exact opposite direction: pick v\mathbf{v}v to point in the exact opposite direction to ∇wL(w)\nabla_{\mathbf{w}} L(\mathbf{w})∇w​L(w)!

This brings us to one of the most important mathematical concepts in machine learning: the direction of steepest decent points in the direction of −∇wL(w)-\nabla_{\mathbf{w}}L(\mathbf{w})−∇w​L(w). Thus our informal algorithm can be rewritten as follows.

  1. Start with a random choice for the initial parameters w\mathbf{w}w.
  2. Compute ∇wL(w)\nabla_{\mathbf{w}} L(\mathbf{w})∇w​L(w).
  3. Take a small step in the opposite of that direction: w←w−ϵ∇wL(w)\mathbf{w} \leftarrow \mathbf{w} - \epsilon\nabla_{\mathbf{w}} L(\mathbf{w})w←w−ϵ∇w​L(w).
  4. Repeat.

This basic algorithm has been modified and adapted many ways by many researchers, but the core concept remains the same in all of them. Use the gradient to find the direction that decreases the loss as rapidly as possible, and update the parameters to take a step in that direction.

A Note on Mathematical Optimization

Throughout this book, we focus squarely on numerical optimization techniques for the practical reason that all functions we encounter in the deep learning setting are too complex to minimize explicitly.

However, it is a useful exercise to consider what the geometric understanding we obtained above tells us about optimizing functions directly.

Suppose that we wish to find the value of x0\mathbf{x}_0x0​ which minimizes some function L(x)L(\mathbf{x})L(x). Let's suppose that moreover someone gives us a value and tells us that it is the value that minimizes LLL. Is there anything we can check to see if their answer is even plausible?

Again consider (see equation above):

L(x0+ϵ)≈L(x0)+ϵ⋅∇xL(x0).L(\mathbf{x}_0 + \boldsymbol{\epsilon}) \approx L(\mathbf{x}_0) + \boldsymbol{\epsilon}\cdot \nabla_{\mathbf{x}} L(\mathbf{x}_0).L(x0​+ϵ)≈L(x0​)+ϵ⋅∇x​L(x0​).

If the gradient is not zero, we know that we can take a step in the direction −ϵ∇xL(x0)-\epsilon \nabla_{\mathbf{x}} L(\mathbf{x}_0)−ϵ∇x​L(x0​) to find a value of LLL that is smaller. Thus, if we truly are at a minimum, this cannot be the case! We can conclude that if x0\mathbf{x}_0x0​ is a minimum, then ∇xL(x0)=0\nabla_{\mathbf{x}} L(\mathbf{x}_0) = 0∇x​L(x0​)=0. We call points with ∇xL(x0)=0\nabla_{\mathbf{x}} L(\mathbf{x}_0) = 0∇x​L(x0​)=0 critical points.

This is nice, because in some rare settings, we can explicitly find all the points where the gradient is zero, and find the one with the smallest value.

For a concrete example, consider the function

f(x)=3x4−4x3−12x2.f(x) = 3x^4 - 4x^3 -12x^2.f(x)=3x4−4x3−12x2.

This function has derivative

dfdx=12x3−12x2−24x=12x(x−2)(x+1).\frac{df}{dx} = 12x^3 - 12x^2 -24x = 12x(x-2)(x+1).dxdf​=12x3−12x2−24x=12x(x−2)(x+1).

The only possible location of minima are at x=−1,0,2x = -1, 0, 2x=−1,0,2, where the function takes the values −5,0,−32-5,0, -32−5,0,−32 respectively, and thus we can conclude that we minimize our function when x=2x = 2x=2. A quick plot confirms this.

x = torch.arange(-2, 3, 0.01)
f = (3 * x**4) - (4 * x**3) - (12 * x**2)

d2l.plot(x, f, 'x', 'f(x)')

This highlights an important fact to know when working either theoretically or numerically: the only possible points where we can minimize (or maximize) a function will have gradient equal to zero, however, not every point with gradient zero is the true global minimum (or maximum).

The fact that we compute derivatives from fff back towards the inputs rather than from the inputs forward to the outputs (as we did in the first code snippet above) is what gives this algorithm its name: backpropagation. Note that there are two steps:

  1. Compute the value of the function, and the single step partials from front to back. While not done above, this can be combined into a single forward pass.
  2. Compute the gradient of fff from back to front. We call this the backwards pass.

This is precisely what every deep learning algorithm implements to allow the computation of the gradient of the loss with respect to every weight in the network at one pass. It is an astonishing fact that we have such a decomposition.

To see how to encapsulated this, let's take a quick look at this example.

y = torch.tensor([-2.], requires_grad=True)

# Do the computation like usual, tracking gradients

u, v = (a + b)**2, (a - b)**2

# Execute backward pass

      f'{z.data.item()} is {w.grad.data.item()}')

      f'{z.data.item()} is {x.grad.data.item()}')

As with single variable calculus, it is useful to consider higher-order derivatives in order to get a handle on how we can obtain a better approximation to a function than using the gradient alone.

There is one immediate problem one encounters when working with higher order derivatives of functions of several variables, and that is there are a large number of them. Derivatives of functions involving matrices turn out to be particularly nice. This required significantly more work than our last one, but the final result is small. More than that, consider the following computation for traditional single variable derivatives:

ddx(xax)=dxdxax+xadxdx=(a+a)x.\frac{d}{dx}(xax) = \frac{dx}{dx}ax + xa\frac{dx}{dx} = (a+a)x.dxd​(xax)=dxdx​ax+xadxdx​=(a+a)x.

Equivalently ddx(ax2)=2ax=(a+a)x\frac{d}{dx}(ax^2) = 2ax = (a+a)xdxd​(ax2)=2ax=(a+a)x. Again, we get a result that looks rather like the single variable result but with a transpose tossed in.

At this point, the pattern should be looking rather suspicious, so let's try to figure out why. When we take matrix derivatives like this, let's first assume that the expression we get will be another matrix expression: an expression we can write it in terms of products and sums of matrices and their transposes. If such an expression exists, it will need to be true for all matrices. In particular, it will need to be true of 1×11 \times 11×1 matrices, in which case the matrix product is just the product of the numbers, the matrix sum is just the sum, and the transpose does nothing at all! In other words, whatever expression we get must match the single variable expression. This means that, with some practice, one can often guess matrix derivatives just by knowing what the associated single variable expression must look like!

Let's try this out. Suppose that X\mathbf{X}X is a n×mn \times mn×m matrix, U\mathbf{U}U is an n×rn \times rn×r and V\mathbf{V}V is an r×mr \times mr×m. Let's try to compute

ddV∥X−UV∥22=  ?\frac{d}{d\mathbf{V}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2} = \;?dVd​∥X−UV∥22​=? This computation is important in an area called matrix factorization. For us, however, it is just a derivative to compute. Let's try to imagine what this would be for 1×11\times11×1 matrices. In that case, we get the expression

ddv(x−uv)2=−2(x−uv)u,\frac{d}{dv} (x-uv)^{2}= -2(x-uv)u,dvd​(x−uv)2=−2(x−uv)u,

where, the derivative is rather standard. If we try to convert this back into a matrix expression we get

ddV∥X−UV∥22=−2(X−UV)U.\frac{d}{d\mathbf{V}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= -2(\mathbf{X} - \mathbf{U}\mathbf{V})\mathbf{U}.dVd​∥X−UV∥22​=−2(X−UV)U.

However, if we look at this it does not quite work. Recall that X\mathbf{X}X is n×mn \times mn×m, as is UV\mathbf{U}\mathbf{V}UV, so the matrix 2(X−UV)2(\mathbf{X} - \mathbf{U}\mathbf{V})2(X−UV) is n×mn \times mn×m. On the other hand U\mathbf{U}U is n×rn \times rn×r, and we cannot multiply a n×mn \times mn×m and a n×rn \times rn×r matrix since the dimensions do not match!

We want to get ddV\frac{d}{d\mathbf{V}}dVd​, which is the same shape as V\mathbf{V}V, which is r×mr \times mr×m. So somehow we need to take a n×mn \times mn×m matrix and a n×rn \times rn×r matrix, multiply them together (perhaps with some transposes) to get a r×mr \times mr×m. We can do this by multiplying U⊤U^\topU⊤ by (X−UV)(\mathbf{X} - \mathbf{U}\mathbf{V})(X−UV). Thus, we can guess the solution to (see equation above) is

ddV∥X−UV∥22=−2U⊤(X−UV).\frac{d}{d\mathbf{V}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= -2\mathbf{U}^\top(\mathbf{X} - \mathbf{U}\mathbf{V}).dVd​∥X−UV∥22​=−2U⊤(X−UV).

To show that this works, we would be remiss to not provide a detailed computation. If we already believe that this rule-of-thumb works, feel free to skip past this derivation. To compute

ddV∥X−UV∥22,\frac{d}{d\mathbf{V}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^2,dVd​∥X−UV∥22​,

we must find for every aaa, and bbb

ddvab∥X−UV∥22=ddvab∑i,j(xij−∑kuikvkj)2.\frac{d}{dv_{ab}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= \frac{d}{dv_{ab}} \sum_{i, j}\left(x_{ij} - \sum_k u_{ik}v_{kj}\right)^2.dvab​d​∥X−UV∥22​=dvab​d​i,j∑​(xij​−k∑​uik​vkj​)2.

Recalling that all entries of X\mathbf{X}X and U\mathbf{U}U are constants as far as ddvab\frac{d}{dv_{ab}}dvab​d​ is concerned, we may push the derivative inside the sum, and apply the chain rule to the square to get

ddvab∥X−UV∥22=∑i,j2(xij−∑kuikvkj)(−∑kuikdvkjdvab).\frac{d}{dv_{ab}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= \sum_{i, j}2\left(x_{ij} - \sum_k u_{ik}v_{kj}\right)\left(-\sum_k u_{ik}\frac{dv_{kj}}{dv_{ab}} \right).dvab​d​∥X−UV∥22​=i,j∑​2(xij​−k∑​uik​vkj​)(−k∑​uik​dvab​dvkj​​).

As in the previous derivation, we may note that dvkjdvab\frac{dv_{kj}}{dv_{ab}}dvab​dvkj​​ is only non-zero if the k=ak=ak=a and j=bj=bj=b. If either of those conditions do not hold, the term in the sum is zero, and we may freely discard it. We see that

ddvab∥X−UV∥22=−2∑i(xib−∑kuikvkb)uia.\frac{d}{dv_{ab}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= -2\sum_{i}\left(x_{ib} - \sum_k u_{ik}v_{kb}\right)u_{ia}.dvab​d​∥X−UV∥22​=−2i∑​(xib​−k∑​uik​vkb​)uia​.

An important subtlety here is that the requirement that k=ak=ak=a does not occur inside the inner sum since that kkk is a dummy variable which we are summing over inside the inner term. For a notationally cleaner example, consider why

ddx1(∑ixi)2=2(∑ixi).\frac{d}{dx_1} \left(\sum_i x_i \right)^{2}= 2\left(\sum_i x_i \right).dx1​d​(i∑​xi​)2=2(i∑​xi​).

From this point, we may start identifying components of the sum. First,

∑kuikvkb=[UV]ib.\sum_k u_{ik}v_{kb} = [\mathbf{U}\mathbf{V}]_{ib}.k∑​uik​vkb​=[UV]ib​.

So the entire expression in the inside of the sum is

xib−∑kuikvkb=[X−UV]ib.x_{ib} - \sum_k u_{ik}v_{kb} = [\mathbf{X}-\mathbf{U}\mathbf{V}]_{ib}.xib​−k∑​uik​vkb​=[X−UV]ib​.

This means we may now write our derivative as

ddvab∥X−UV∥22=−2∑i[X−UV]ibuia.\frac{d}{dv_{ab}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= -2\sum_{i}[\mathbf{X}-\mathbf{U}\mathbf{V}]_{ib}u_{ia}.dvab​d​∥X−UV∥22​=−2i∑​[X−UV]ib​uia​.

We want this to look like the a,ba, ba,b element of a matrix so we can use the technique as in the previous example to arrive at a matrix expression, which means that we need to exchange the order of the indices on uiau_{ia}uia​. If we notice that uia=[U⊤]aiu_{ia} = [\mathbf{U}^\top]_{ai}uia​=[U⊤]ai​, we can then write

ddvab∥X−UV∥22=−2∑i[U⊤]ai[X−UV]ib.\frac{d}{dv_{ab}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= -2\sum_{i} [\mathbf{U}^\top]_{ai}[\mathbf{X}-\mathbf{U}\mathbf{V}]_{ib}.dvab​d​∥X−UV∥22​=−2i∑​[U⊤]ai​[X−UV]ib​.

This is a matrix product, and thus we can conclude that

ddvab∥X−UV∥22=−2[U⊤(X−UV)]ab.\frac{d}{dv_{ab}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= -2[\mathbf{U}^\top(\mathbf{X}-\mathbf{U}\mathbf{V})]_{ab}.dvab​d​∥X−UV∥22​=−2[U⊤(X−UV)]ab​.

and thus we may write the solution to (see equation above)

ddV∥X−UV∥22=−2U⊤(X−UV).\frac{d}{d\mathbf{V}} \|\mathbf{X} - \mathbf{U}\mathbf{V}\|_2^{2}= -2\mathbf{U}^\top(\mathbf{X} - \mathbf{U}\mathbf{V}).dVd​∥X−UV∥22​=−2U⊤(X−UV).

This matches the solution we guessed above!

It is reasonable to ask at this point, "Why can I not just write down matrix versions of all the calculus rules I have learned? It is clear this is still mechanical. Why do we not just get it over with!" And indeed there are such rules and (Petersen et al.) provides an excellent summary. However, due to the plethora of ways matrix operations can be combined compared to single values, there are many more matrix derivative rules than single variable ones. It is often the case that it is best to work with the indices, or leave it up to automatic differentiation when appropriate.

Summary

  • In higher dimensions, we can define gradients which serve the same purpose as derivatives in one dimension. These allow us to see how a multi-variable function changes when we make an arbitrary small change to the inputs.
  • The backpropagation algorithm can be seen to be a method of organizing the multi-variable chain rule to allow for the efficient computation of many partial derivatives.
  • Matrix calculus allows us to write the derivatives of matrix expressions in concise ways.
