Naive Bayes

Throughout the previous sections, we learned about the theory of probability and random variables. To put this theory to work, let's introduce the naive Bayes classifier. This uses nothing but probabilistic fundamentals to allow us to perform classification of digits.

Learning is all about making assumptions. If we want to classify a new data example that we have never seen before we have to make some assumptions about which data examples are similar to each other. The naive Bayes classifier, a popular and remarkably clear algorithm, assumes all features are independent from each other to simplify the computation. In this section, we will apply this model to recognize characters in images.

Optical Character Recognition

MNIST (LeCun et al.) is one of widely used datasets. It contains 60,000 images for training and 10,000 images for validation. Each image contains a handwritten digit from 0 to 9. The task is classifying each image into the corresponding digit.

Gluon provides a MNIST class in the data.vision module to automatically retrieve the dataset from the Internet. Subsequently, Gluon will use the already-downloaded local copy. We specify whether we are requesting the training set or the test set by setting the value of the parameter train to True or False, respectively. Each image is a grayscale image with both width and height of 282828 with shape (282828,282828,111). We use a customized transformation to remove the last channel dimension. In addition, the dataset represents each pixel by an unsigned 888-bit integer. We quantize them into binary features to simplify the problem.

data_transform = torchvision.transforms.Compose([

])

mnist_train = torchvision.datasets.MNIST(

mnist_test = torchvision.datasets.MNIST(

The Probabilistic Model for Classification

In a classification task, we map an example into a category. Here an example is a grayscale 28×2828\times 2828×28 image, and a category is a digit. (Refer to (see related section) for a more detailed explanation.) One natural way to express the classification task is via the probabilistic question: what is the most likely label given the features (i.e., image pixels)? Denote by x∈Rd\mathbf x\in\mathbb R^dx∈Rd the features of the example and y∈Ry\in\mathbb Ry∈R the label. Here features are image pixels, where we can reshape a 222-dimensional image to a vector so that d=282=784d=28^2=784d=282=784, and labels are digits. The probability of the label given the features is p(y∣x)p(y \mid \mathbf{x})p(y∣x). If we are able to compute these probabilities, which are p(y∣x)p(y \mid \mathbf{x})p(y∣x) for y=0,…,9y=0, \ldots,9y=0,…,9 in our example, then the classifier will output the prediction y^\hat{y}y^​ given by the expression:

y^=argmax p(y∣x).\hat{y} = \mathrm{argmax} \> p(y \mid \mathbf{x}).y^​=argmaxp(y∣x).

Unfortunately, this requires that we estimate p(y∣x)p(y \mid \mathbf{x})p(y∣x) for every value of x=x1,...,xd\mathbf{x} = x_1, ..., x_dx=x1​,...,xd​. Imagine that each feature could take one of 222 values. For example, the feature x1=1x_1 = 1x1​=1 might signify that the word apple appears in a given document and x1=0x_1 = 0x1​=0 would signify that it does not. If we had 303030 such binary features, that would mean that we need to be prepared to classify any of 2302^{30}230 (over 1 billion!) possible values of the input vector x\mathbf{x}x.

Moreover, where is the learning? If we need to see every single possible example in order to predict the corresponding label then we are not really learning a pattern but just memorizing the dataset.

The Naive Bayes Classifier

Fortunately, by making some assumptions about conditional independence, we can introduce some inductive bias and build a model capable of generalizing from a comparatively modest selection of training examples. To begin, let's use Bayes theorem, to express the classifier as

y^=argmaxy p(y∣x)=argmaxy p(x∣y)p(y)p(x).\hat{y} = \mathrm{argmax}_y \> p(y \mid \mathbf{x}) = \mathrm{argmax}_y \> \frac{p( \mathbf{x} \mid y) p(y)}{p(\mathbf{x})}.y^​=argmaxy​p(y∣x)=argmaxy​p(x)p(x∣y)p(y)​.

Note that the denominator is the normalizing term p(x)p(\mathbf{x})p(x) which does not depend on the value of the label yyy. As a result, we only need to worry about comparing the numerator across different values of yyy. Even if calculating the denominator turned out to be intractable, we could get away with ignoring it, so long as we could evaluate the numerator. Fortunately, even if we wanted to recover the normalizing constant, we could. We can always recover the normalization term since ∑yp(y∣x)=1\sum_y p(y \mid \mathbf{x}) = 1∑y​p(y∣x)=1.

Now, let's focus on p(x∣y)p( \mathbf{x} \mid y)p(x∣y). Using the chain rule of probability, we can express the term p(x∣y)p( \mathbf{x} \mid y)p(x∣y) as

p(x1∣y)⋅p(x2∣x1,y)⋅...⋅p(xd∣x1,...,xd−1,y).p(x_1 \mid y) \cdot p(x_2 \mid x_1, y) \cdot ... \cdot p( x_d \mid x_1, ..., x_{d-1}, y).p(x1​∣y)⋅p(x2​∣x1​,y)⋅...⋅p(xd​∣x1​,...,xd−1​,y).

By itself, this expression does not get us any further. We still must estimate roughly 2d2^d2d parameters. However, if we assume that the features are conditionally independent of each other, given the label, then suddenly we are in much better shape, as this term simplifies to ∏ip(xi∣y)\prod_i p(x_i \mid y)∏i​p(xi​∣y), giving us the predictor

y^=argmaxy ∏i=1dp(xi∣y)p(y).\hat{y} = \mathrm{argmax}_y \> \prod_{i=1}^d p(x_i \mid y) p(y).y^​=argmaxy​∏i=1d​p(xi​∣y)p(y).

If we can estimate p(xi=1∣y)p(x_i=1 \mid y)p(xi​=1∣y) for every iii and yyy, and save its value in Pxy[i,y]P_{xy}[i, y]Pxy​[i,y], here PxyP_{xy}Pxy​ is a d×nd\times nd×n matrix with nnn being the number of classes and y∈{1,…,n}y\in\{1, \ldots, n\}y∈{1,…,n}, then we can also use this to estimate p(xi=0∣y)p(x_i = 0 \mid y)p(xi​=0∣y), i.e.,

p(xi=ti∣y)={Pxy[i,y]for ti=1;1−Pxy[i,y]for ti=0.p(x_i = t_i \mid y) = \begin{cases} P_{xy}[i, y] & \textrm{for } t_i=1 ;\\ 1 - P_{xy}[i, y] & \textrm{for } t_i = 0 . \end{cases}p(xi​=ti​∣y)={Pxy​[i,y]1−Pxy​[i,y]​for ti​=1;for ti​=0.​

In addition, we estimate p(y)p(y)p(y) for every yyy and save it in Py[y]P_y[y]Py​[y], with PyP_yPy​ a nnn-length vector. Then, for any new example t=(t1,t2,…,td)\mathbf t = (t_1, t_2, \ldots, t_d)t=(t1​,t2​,…,td​), we could compute

y^=argmaxy p(y)∏i=1dp(xt=ti∣y)=argmaxy Py[y]∏i=1d Pxy[i,y]ti (1−Pxy[i,y])1−ti\begin{aligned}\hat{y} &= \mathrm{argmax}_ y \ p(y)\prod_{i=1}^d p(x_t = t_i \mid y) \\ &= \mathrm{argmax}_y \ P_y[y]\prod_{i=1}^d \ P_{xy}[i, y]^{t_i}\, \left(1 - P_{xy}[i, y]\right)^{1-t_i}\end{aligned}y^​​=argmaxy​ p(y)i=1∏d​p(xt​=ti​∣y)=argmaxy​ Py​[y]i=1∏d​ Pxy​[i,y]ti​(1−Pxy​[i,y])1−ti​​ for any yyy. So our assumption of conditional independence has taken the complexity of our model from an exponential dependence on the number of features O(2dn)\mathcal{O}(2^dn)O(2dn) to a linear dependence, which is O(dn)\mathcal{O}(dn)O(dn).

Training

The problem now is that we do not know PxyP_{xy}Pxy​ and PyP_yPy​. So we need to estimate their values given some training data first. This is training the model. Estimating PyP_yPy​ is not too hard. Since we are only dealing with 101010 classes, we may count the number of occurrences nyn_yny​ for each of the digits and divide it by the total amount of data nnn. For instance, if digit 8 occurs n8=5,800n_8 = 5,800n8​=5,800 times and we have a total of n=60,000n = 60,000n=60,000 images, the probability estimate is p(y=8)=0.0967p(y=8) = 0.0967p(y=8)=0.0967.

X = torch.stack([mnist_train[i][0] for i in range(len(mnist_train))], dim=0)
Y = torch.tensor([mnist_train[i][1] for i in range(len(mnist_train))])

n_y = torch.zeros(10)
for y in range(10):
    n_y[y] = (Y == y).sum()
P_y = n_y / n_y.sum()
P_y

Now on to slightly more difficult things PxyP_{xy}Pxy​. Since we picked black and white images, p(xi∣y)p(x_i \mid y)p(xi​∣y) denotes the probability that pixel iii is switched on for class yyy. Just like before we can go and count the number of times niyn_{iy}niy​ such that an event occurs and divide it by the total number of occurrences of yyy, i.e., nyn_yny​. But there is something slightly troubling: certain pixels may never be black (e.g., for well cropped images the corner pixels might always be white). A convenient way for statisticians to deal with this problem is to add pseudo counts to all occurrences. Hence, rather than niyn_{iy}niy​ we use niy+1n_{iy}+1niy​+1 and instead of nyn_yny​ we use ny+2n_{y}+2ny​+2 (since there are two possible values pixel iii can take - it can either be black or white). This is also called Laplace Smoothing. It may seem ad-hoc, however it can be motivated from a Bayesian point-of-view by a Beta-binomial model.

n_x = torch.zeros((10, 28, 28))
for y in range(10):
    n_x[y] = torch.tensor(X.numpy()[Y.numpy() == y].sum(axis=0))
P_xy = (n_x + 1) / (n_y + 2).reshape(10, 1, 1)

d2l.show_images(P_xy, 2, 5);

By visualizing these 10×28×2810\times 28\times 2810×28×28 probabilities (for each pixel for each class) we could get some mean looking digits.

Now we can use (see equation above) to predict a new image. Given x\mathbf xx, the following functions computes p(x∣y)p(y)p(\mathbf x \mid y)p(y)p(x∣y)p(y) for every yyy.

def bayes_pred(x):
    x = x.unsqueeze(0)  # (28, 28) -> (1, 28, 28)
    p_xy = P_xy * x + (1 - P_xy)*(1 - x)
    p_xy = p_xy.reshape(10, -1).prod(dim=1)  # p(x|y)
    return p_xy * P_y

image, label = mnist_test[0]
bayes_pred(image)

This went horribly wrong! To find out why, let's look at the per pixel probabilities. They are typically numbers between 0.0010.0010.001 and 111. We are multiplying 784784784 of them. At this point it is worth mentioning that we are calculating these numbers on a computer, hence with a fixed range for the exponent. What happens is that we experience numerical underflow, i.e., multiplying all the small numbers leads to something even smaller until it is rounded down to zero. We discussed this as a theoretical issue in (see related section), but we see the phenomena clearly here in practice.

As discussed in that section, we fix this by use the fact that log⁡ab=log⁡a+log⁡b\log a b = \log a + \log blogab=loga+logb, i.e., we switch to summing logarithms. Even if both aaa and bbb are small numbers, the logarithm values should be in a proper range.

a = 0.1
print('underflow:', a**784)
print('logarithm is normal:', 784*math.log(a))

Since the logarithm is an increasing function, we can rewrite (see equation above) as

y^=argmaxy log⁡Py[y]+∑i=1d[tilog⁡Pxy[xi,y]+(1−ti)log⁡(1−Pxy[xi,y])]. \hat{y} = \mathrm{argmax}_y \ \log P_y[y] + \sum_{i=1}^d \Big[t_i\log P_{xy}[x_i, y] + (1-t_i) \log (1 - P_{xy}[x_i, y]) \Big].y^​=argmaxy​ logPy​[y]+∑i=1d​[ti​logPxy​[xi​,y]+(1−ti​)log(1−Pxy​[xi​,y])].

We can implement the following stable version:

log_P_xy = torch.log(P_xy)
log_P_xy_neg = torch.log(1 - P_xy)
log_P_y = torch.log(P_y)

def bayes_pred_stable(x):
    x = x.unsqueeze(0)  # (28, 28) -> (1, 28, 28)
    p_xy = log_P_xy * x + log_P_xy_neg * (1 - x)
    p_xy = p_xy.reshape(10, -1).sum(axis=1)  # p(x|y)
    return p_xy + log_P_y

py = bayes_pred_stable(image)
py

We may now check if the prediction is correct.

py.argmax(dim=0) == label

If we now predict a few validation examples, we can see the Bayes classifier works pretty well.

def predict(X):
    return [bayes_pred_stable(x).argmax(dim=0).type(torch.int32).item()
            for x in X]

X = torch.stack([mnist_test[i][0] for i in range(18)], dim=0)
y = torch.tensor([mnist_test[i][1] for i in range(18)])
preds = predict(X)
d2l.show_images(X, 2, 9, titles=[str(d) for d in preds]);

Finally, let's compute the overall accuracy of the classifier.

X = torch.stack([mnist_test[i][0] for i in range(len(mnist_test))], dim=0)
y = torch.tensor([mnist_test[i][1] for i in range(len(mnist_test))])
preds = torch.tensor(predict(X), dtype=torch.int32)
float((preds == y).sum()) / len(y)  # Validation accuracy

Modern deep networks achieve error rates of less than 0.010.010.01. The relatively poor performance is due to the incorrect statistical assumptions that we made in our model: we assumed that each and every pixel are independently generated, depending only on the label. This is clearly not how humans write digits, and this wrong assumption led to the downfall of our overly naive (Bayes) classifier.

Anlatım06 / 08

Summary

  • Using Bayes' rule, a classifier can be made by assuming all observed features are independent.
  • This classifier can be trained on a dataset by counting the number of occurrences of combinations of labels and pixel values.
  • This classifier was the gold standard for decades for tasks such as spam detection.
