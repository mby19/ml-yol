Anlatım01 / 10

Proje: telefondaki modelin sözleşmesi

Bu projede bir modeli "çalışıyor" hâlden "cihazda yayına hazır" hâle getiriyorsunuz. Farkı şu: eğitim scriptinizin doğruluğu iyi olabilir; ama cihazda model bir dosya, bir bellek bütçesi, bir gecikme sözleşmesi ve bir sürüm numarasıdır. Proje bu dört şeyi üretmenizi istiyor.

Kapsam: iki izlekten birini seçin

İzlek A — görüntü sınıflandırma. 8x8 el yazısı rakamlar (sklearn load_digits, 1797 örnek) veya kendi küçük görsel setiniz. Girdi gri ton, 10 sınıf. Çıktı: sınıf olasılıkları.

İzlek B — metin sınıflandırma. Kısa metin (niyet/duygu) sınıflandırması. Özellik: karakter n-gram hashing (boyut 512) veya gömme ortalaması; model: küçük MLP (≤ 50k parametre) ya da lojistik regresyon. Veri: kendi etiketli 500-2000 kısa cümle ya da açık bir küçük set. Bu izlekte ön işleme hattı da artefaktır: tokenizer'ın cihazda aynı çıktıyı vermesi gerekir.

İki izlek de aynı teslim setini üretir. Aşağıdaki kod İzlek A'nın tamamını çalıştırır; İzlek B'de Net yerine kendi modelinizi koyup gömme/ön işleme adımını ayrı bir fonksiyon olarak sabitlersiniz.

Teslimler (dördü de zorunlu)

  1. Artefakt seti. En az iki format: ONNX (int8) ve Core ML (mlprogram, fp16). Batch 1'de çalışır, dinamik batch destekliyorsa sınırı yazılı.
  2. Model kartı (model_card.json). Parametre, doğruluk, her varyant için boyut/gecikme, seçilen varyant, girdi-çıktı sözleşmesi (isim, şekil, dtype, ön işleme), toleranslar, bilinen sınırlar.
  3. Ölçüm raporu. Isınmış p50/p95/p99, ısıl sapma (ilk %10 vs son %10 medyan), bütçe kapısı sonucu. Tek sayı değil, dağılım.
  4. Uygulama entegrasyonu. Gerçek bir uygulamada çalışan en az bir yol: iOS (Swift + Core ML) veya Android (Kotlin + LiteRT/ORT) ya da masaüstü demo (Python/ORT) + ekran görüntüsü. Cihaz yoksa masaüstü demo kabul; ama cihaz ölçümü yerine geçmez, bunu raporda yazın.

Anlatım03 / 10

Beş aşama, beş çıktı

Projeyi aşamalara bölün; her aşamanın tek çıktısı olsun. Aşama çıktısı olmadan sonrakine geçmeyin — cihaz işlerinde geri dönüş pahalıdır çünkü ölçüm ortamı değişir.

Aşama 1 — Baseline ve bütçe (≈ 60 dk)

Baseline: modeli eğitin, doğrulama setiyle erken durdurun, test setinde tek bir doğruluk sayısı üretin. Aynı anda bütçeyi yazın: boyut (KB), p95 (ms), minimum doğruluk. Bütçe yoksa proje yoktur; "mümkün olduğunca hızlı" bir hedef değildir.

Çıktı: baseline.json — parametre, val_acc, test_acc, süre.

Aşama 2 — Dışa aktarma ve denklik (≈ 90 dk)

torch.export ile yakalayın, ONNX'e yazın, ORT'de çalıştırın. 500 örnekte argmax ve fark raporu üretin. Batch 1 ve (destekliyorsa) batch 8 ile deneyin. Core ML varsa .mlpackage üretip aynı testi tekrarlayın.

Çıktı: export_report.json — opset, girdi/çıktı sözleşmesi, denklik sayıları.

Sık hata: dinamik export'ta value_info çelişkisi; çözümü ders 2'de. Batch 1 örneğiyle dinamik eksen tanımlamaya çalışmak ConstraintViolationError verir; batch 4 örneği kullanın.

Aşama 3 — Optimizasyon (≈ 120 dk)

İki varyant üretin: int8 ve (gerekiyorsa) 4-bit. Her biri için boyut, doğruluk, p50. Roofline ile neden hızlandığını ya da hızlanmadığını açıklayın. Budama ve damıtma opsiyonel; yaparsanız ince ayarsız/ince ayarlı iki sayı raporlayın.

Çıktı: variants.json — tablo + "neden bu varyant" paragrafı.

Aşama 4 — Ölçüm protokolü (≈ 90 dk)

Isınma (100 çağrı), ölçüm (1000 çağrı), p50/p95/p99, ısıl sapma, bütçe kapısı. Masaüstünde ölçtüyseniz cihaz tahminini ayrı bir sütunda verin ve varsayımı yazın (bant genişliği oranı, çekirdek sayısı). Cihazda ölçtüyseniz hangi cihaz, hangi işletim sistemi, hangi güç modu — hepsi raporda.

Çıktı: bench.json + bir paragraflık yorum.

Aşama 5 — Entegrasyon ve model kartı (≈ 180 dk)

Uygulamaya gömün: modeli açılışta yükleyin, ilk çıkarımı arka planda ısıtın, sonucu ana iş parçacığı dışında üretin, hata durumunda (model yüklenemedi) makul bir yedek davranış gösterin. Model kartını yazın: her sayının yanında ölçüm mü tahmin mi olduğu yazılı olsun.

// iOS — Core ML: model bir kez yüklenir, çıkarım arka planda
final class DigitClassifier {
    private let model: MLModel                // uygulama açılışında bir kez
    private let queue = DispatchQueue(label: "inference", qos: .userInitiated)
    init?() {
        guard let url = Bundle.main.url(forResource: "Tiny", withExtension: "mlmodelc"),
              let ml = try? MLModel(contentsOf: url) else { return nil }
        self.model = ml
    }
    func predict(_ pixels: [Float], completion: @escaping (Int?) -> Void) {   // 64 değer, [0,1]
        guard let input = try? MLMultiArray(shape: [1, 1, 8, 8] as [NSNumber], dataType: .float32) else {
            completion(nil); return
        }
        for i in 0..<64 { input[i] = NSNumber(value: pixels[i]) }
        queue.async {
            guard let out = try? self.model.prediction(
                    from: MLDictionaryFeatureProvider(
                        dictionary: ["img": MLFeatureValue(multiArray: input)])),
                  let logits = out.featureValue(for: "logits")?.multiArrayValue else {
                completion(nil); return
            }
            completion((0..<logits.count).max { logits[$0].floatValue < logits[$1].floatValue })
        }
    }
}

Aşama 2'deki dönüşüm tensör girdi/çıktı üretir (img → logits), sınıf etiketi değil: bu yüzden Vision'ın VNClassificationObservation yolu değil, MLModel.prediction(from:) + elle argmax kullanılır. Modelin sözleşmesi (isim, şekil, dtype) model kartındakiyle aynı olmak zorunda.

// Android — LiteRT: mmap ile yükle, tek Interpreter, arka planda çalıştır
class DigitClassifier(context: Context) {
    private val interpreter = Interpreter(
        FileUtil.loadMappedFile(context, "tinycnn.tflite"),
        Interpreter.Options().apply { setNumThreads(1) }
    )
    private val input = Array(1) { Array(1) { Array(8) { FloatArray(8) } } }
    private val output = Array(1) { FloatArray(10) }

    fun predict(pixels: FloatArray): Int = synchronized(interpreter) {
        for (r in 0 until 8) for (c in 0 until 8) input[0][0][r][c] = pixels[r * 8 + c]
        interpreter.run(input, output)
        output[0].indices.maxBy { output[0][it] }
    }
}

Kod04 / 10

Uçtan uca hat: eğitim (erken durdurma), ONNX fp32/int8, Core ML fp16, bütçe kapısı ve model kartı. Çıktı, bütçeyi kim geçti kim kaldı gösteriyor — ort_fp32 konteyner yükü yüzünden 64 KB bütçesini 1.2 KB ile kaçırıyor.

# test: python 3.13 · coremltools 9.0 · onnxruntime 1.31.1 · scikit-learn 1.9.1
# PC'de çalıştır (macOS) — gerekli: numpy, torch, onnx, onnxruntime, coremltools, scikit-learn
# Uçtan uca: eğit -> export -> kuantize -> ölç -> bütçe kapısı -> model kartı.
import json, os, glob, time, numpy as np, torch, torch.nn as nn, onnx
import onnxruntime as ort
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

torch.set_num_threads(1); torch.manual_seed(0)
d = load_digits(); X = d.images.astype("float32")[:, None] / 16.0; y = d.target
Xtr, Xtmp, ytr, ytmp = train_test_split(X, y, test_size=0.4, random_state=0, stratify=y)
Xva, Xte, yva, yte = train_test_split(Xtmp, ytmp, test_size=0.5, random_state=0, stratify=ytmp)

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.f = nn.Sequential(nn.Conv2d(1, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
                               nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
                               nn.Flatten(), nn.Linear(128, 64), nn.ReLU(), nn.Linear(64, 10))
    def forward(self, x): return self.f(x)

def fit(model, epochs=30, lr=3e-3):
    opt = torch.optim.Adam(model.parameters(), lr)
    xt, yt = torch.from_numpy(Xtr), torch.from_numpy(ytr)
    best, best_state = 0.0, None
    for ep in range(epochs):
        perm = torch.randperm(len(xt))
        for i in range(0, len(xt), 64):
            idx = perm[i:i+64]
            loss = nn.functional.cross_entropy(model(xt[idx]), yt[idx])
            opt.zero_grad(); loss.backward(); opt.step()
        with torch.inference_mode():                     # erken durdurma: doğrulama seti
            va = float((model(torch.from_numpy(Xva)).argmax(1) == torch.from_numpy(yva)).float().mean())
        if va > best: best, best_state = va, {k: v.clone() for k, v in model.state_dict().items()}
    model.load_state_dict(best_state)
    return model, best

model, val_acc = fit(Net())
m = model.eval()
print(f"eğitim: param={sum(p.numel() for p in m.parameters())} val_acc={val_acc:.4f}")

x4 = torch.from_numpy(Xte[:4])
batch = torch.export.Dim("batch", min=1, max=64)
torch.onnx.export(m, (x4,), "/tmp/app.onnx", dynamo=True, input_names=["img"],
                  output_names=["logits"], dynamic_shapes={"x": {0: batch}})
g = onnx.load("/tmp/app.onnx"); g.graph.ClearField("value_info"); onnx.save(g, "/tmp/app.onnx")
from onnxruntime.quantization import quantize_dynamic, QuantType
quantize_dynamic("/tmp/app.onnx", "/tmp/app8.onnx", weight_type=QuantType.QInt8)

so = ort.SessionOptions(); so.intra_op_num_threads = 1; so.inter_op_num_threads = 1
sessions = {"ort_fp32": ort.InferenceSession("/tmp/app.onnx", so, providers=["CPUExecutionProvider"]),
            "ort_int8": ort.InferenceSession("/tmp/app8.onnx", so, providers=["CPUExecutionProvider"])}

def lat_us(fn, n=400, warm=40):
    for _ in range(warm): fn()
    ts = []
    for _ in range(n):
        t = time.perf_counter_ns(); fn(); ts.append((time.perf_counter_ns() - t) / 1e3)
    a = np.array(ts)
    return np.percentile(a, 50), np.percentile(a, 95)

report = {"model": "digits_cnn", "params": sum(p.numel() for p in m.parameters()),
          "val_acc": round(val_acc, 4), "runs": {}}
with torch.inference_mode():
    p50, p95 = lat_us(lambda: m(torch.from_numpy(Xte[:1])))
    acc = float((m(torch.from_numpy(Xte)).argmax(1) == torch.from_numpy(yte)).float().mean())
report["runs"]["torch"] = {"size_kb": round(sum(p.numel() for p in m.parameters()) * 4 / 1024, 1),
                           "test_acc": round(acc, 4), "p50_us": round(p50, 1), "p95_us": round(p95, 1)}
for name, sess in sessions.items():
    path = "/tmp/app8.onnx" if "int8" in name else "/tmp/app.onnx"
    out = np.concatenate([sess.run(None, {"img": Xte[i:i+8]})[0] for i in range(0, len(Xte), 8)])
    p50, p95 = lat_us(lambda: sess.run(None, {"img": Xte[:1]}))
    report["runs"][name] = {"size_kb": round(os.path.getsize(path) / 1024, 1),
                            "test_acc": round(float((out.argmax(1) == yte).mean()), 4),
                            "p50_us": round(p50, 1), "p95_us": round(p95, 1)}

import coremltools as ct
pkg = ct.convert(torch.jit.trace(m, torch.randn(1, 1, 8, 8)),
                 inputs=[ct.TensorType(name="img", shape=(1, 1, 8, 8))],
                 outputs=[ct.TensorType(name="logits")], convert_to="mlprogram",
                 minimum_deployment_target=ct.target.iOS18)
pkg.save("/tmp/app.mlpackage")
wbytes = sum(os.path.getsize(q) for q in glob.glob(pkg.weights_dir + "/**/*", recursive=True) if os.path.isfile(q))
out = np.array([pkg.predict({"img": Xte[i:i+1]})["logits"][0] for i in range(len(Xte))])
p50, p95 = lat_us(lambda: pkg.predict({"img": Xte[:1]}), n=200)
report["runs"]["coreml_fp16"] = {"size_kb": round(wbytes / 1024, 1),
                                 "test_acc": round(float((out.argmax(1) == yte).mean()), 4),
                                 "p50_us": round(p50, 1), "p95_us": round(p95, 1)}

BUDGET = {"size_kb": 64, "p95_us": 200, "min_acc": 0.95}
print(f"{'varyant':14s} {'boyut_kb':>9s} {'test_acc':>9s} {'p50_us':>7s} {'p95_us':>7s}  bütçe")
for name, r in report["runs"].items():
    ok = (r["size_kb"] <= BUDGET["size_kb"] and r["p95_us"] <= BUDGET["p95_us"]
          and r["test_acc"] >= BUDGET["min_acc"])
    r["passes_budget"] = ok
    print(f"{name:14s} {r['size_kb']:9.1f} {r['test_acc']:9.4f} {r['p50_us']:7.1f} {r['p95_us']:7.1f}  "
          f"{'GEÇTİ' if ok else 'KALDI'}")

chosen = min((k for k, r in report["runs"].items() if r["passes_budget"]),
             key=lambda k: report["runs"][k]["p95_us"])
report["chosen"] = chosen
print("\nseçilen:", chosen)
json.dump(report, open("/tmp/model_card.json", "w"), indent=1, ensure_ascii=False)
print(json.dumps(report["runs"][chosen], ensure_ascii=False), "-> /tmp/model_card.json")

def protocol(fn, n=1000, warm=100):
    for _ in range(warm): fn()                       # ısınma: derleme + bellek havuzu
    ts = []
    for _ in range(n):
        t = time.perf_counter_ns(); fn(); ts.append((time.perf_counter_ns() - t) / 1e3)
    a = np.array(ts); d = len(a) // 10
    return {"n": n, "p50": float(np.percentile(a, 50)), "p95": float(np.percentile(a, 95)),
            "p99": float(np.percentile(a, 99)), "max": float(a.max()),
            "ilk_%10": float(np.median(a[:d])), "son_%10": float(np.median(a[-d:]))}

r = protocol(lambda: sess.run(None, feed))
print(f"p50={r['p50']:.1f}us p95={r['p95']:.1f}us p99={r['p99']:.1f}us max={r['max']:.1f}us")
print(f"ısıl sapma: ilk %10 medyanı {r['ilk_%10']:.1f}us -> son %10 {r['son_%10']:.1f}us "
      f"({100*(r['son_%10']/r['ilk_%10']-1):+.1f}%)")

BUDGET = {"p50": 50.0, "p95": 120.0, "drift": 25.0}     # cihaz bütçenizle değiştirin
checks = {"p50": r["p50"] <= BUDGET["p50"], "p95": r["p95"] <= BUDGET["p95"],
          "drift": 100 * (r["son_%10"] / r["ilk_%10"] - 1) <= BUDGET["drift"]}
for k, ok in checks.items():
    print(f"{k:6s} {'GEÇTİ' if ok else 'KALDI'}")
assert all(checks.values()), "bütçe aşıldı"
json.dump({"olcum": r, "butce": BUDGET, "gecti": checks}, open("/tmp/bench.json", "w"), indent=1)
print("rapor: /tmp/bench.json")

# Beklenen çıktı:
# p50=10.5us p95=12.3us p99=26.5us max=91.4us
# ısıl sapma: ilk %10 medyanı 9.2us -> son %10 10.6us (+15.5%)
# p50    GEÇTİ
# p95    GEÇTİ
# drift  GEÇTİ
# rapor: /tmp/bench.json

p99 (26.5 µs) p50'nin 2.5 katı, max 91 µs: kuyruk gecikmesi gerçek. Isıl sapma %15.5 — masaüstünde bile var; telefonda 3-5 dakikalık koşuda %30-100 görebilirsiniz. Bu yüzden bütçe kapısında p95 ve sapma birlikte kontrol edilir; sadece p50'ye bakan bir kapı, üretimde yavaşlığı kaçırır.

Teslim öncesi son kontrol (kendi kendinize)

  1. Temiz makinede yeniden üretim. python train.py && python export.py && python bench.py komutu, sıfırdan aynı model kartını üretiyor mu? Tohumlar sabit mi?
  2. Denklik. export.py, 500 örnekte argmax uyuşmazlığı ve maksimum farkı yazdırıyor mu? Eşiği aşarsa hata veriyor mu?
  3. Bütçe. bench.py, bütçe aşımında sıfır olmayan çıkış koduyla bitiyor mu? (CI bunu bekler.)
  4. Sınırlar. Model kartında "bilinen sınırlar" var mı: batch sınırı, girdi boyutu/dtype, desteklenmeyen cihaz, doğruluk düşüşü senaryosu?
  5. Uygulama. Model yükleme bir kez mi? İlk çıkarım ısıtılıyor mu? Ana iş parçacığı bloke ediliyor mu? Model yüklenemezse ne oluyor?
  6. Gözlem. Uygulamada çıkarım süresi loglanıyor mu (yerel, kullanıcı izniyle)? Hata oranı görülüyor mu?
  7. Sürüm. Model hash'i ve dönüşüm aracı sürümü kayıtlı mı? Yeni model dağıtımında eski sürüm nasıl geri alınacak?

Öz değerlendirme ölçeği

  • 0-40: Model çalışıyor ama ölçüm/denklik yok. (Prototip)
  • 40-70: Artefakt + ölçüm var; bütçe kapısı ve sınırlar eksik.
  • 70-85: Tüm teslimler var; entegrasyon demo seviyesinde.
  • 85-100: Bütçe CI'da, denklik testi otomatik, ısıl sapma raporlanmış, model kartı eksiksiz, geri alma planı var.

Kontrol07 / 10

Model kartınızda p50 = 12 ms yazıyor, uygulamada kullanıcılar "bazen donuyor" diyor. Kartı nasıl düzeltirsiniz; hangi üç sayıyı eklemek zorunlu?

Cevabı göster

p50 tek başına kullanıcı hissini anlatmaz. Eklenmesi gerekenler: (1) p95 ve p99 (ör. 12 ms / 28 ms / 90 ms); (2) ısıl sapma — ilk %10 ve son %10 medyanı (ör. 11 ms → 19 ms); (3) uçtan uca hat süresi (ön işleme + çıkarım + son işleme), çünkü donma genelde model değil ön işleme veya ana iş parçacığı blokajıdır. Ayrıca ölçüm koşulunu yazın (cihaz, işletim sistemi, güç modu, ısınma yapıldı mı).

Kontrol08 / 10

Bütçe kapınız size_kb <= 64 diyor. ort_fp32 65.2 KB, ort_int8 25.0 KB çıktı. Model ağırlığı 54.8 KB olduğuna göre bu 1.2 KB fark nereden geliyor ve ne yapardınız?

Cevabı göster

Fark, ONNX protobuf konteyner yükü: düğüm tanımları, operatör isimleri, şekil bilgisi, opset bildirimi. Ham ağırlık hesabı (parametre x 4) dosya boyutunu vermez; küçük modellerde bu yük oransal olarak büyük. Yapılacaklar: (1) bütçeyi ham ağırlığa değil dosya boyutuna göre tanımlamak (doğru olan bu); (2) int8'e geçmek (25 KB, hem bütçe hem bellek kazancı); (3) gerekiyorsa ONNX grafiğini sadeleştirmek (kullanılmayan çıktıları, ara isimleri kısaltmak) — kazanç sınırlı, önce int8.

Kontrol09 / 10

Projenizde denklik testi geçiyor (500 örnek, argmax %100) ama sahada doğruluk %8 düşük. İlk üç hipoteziniz ne olur, her birini nasıl test edersiniz?

Cevabı göster

(1) Ön işleme kayması: cihazda gri ton/ölçek/kırpma farklı — test setini cihazın ürettiği ham girdiyle (kamera çıktısı) yeniden oluşturup denklik testini o girdiyle tekrarlayın. (2) Dağılım kayması: sahada gerçek veri test setinden farklı (aydınlatma, arka plan, el yazısı stili) — sahada toplanan 100-200 örnekte doğruluğu ölçün, sınıf bazında hata analizi yapın. (3) Sayısal/hassasiyet: fp16 veya int8, sahada farklı örneklerde sınır vakaları bozuyor — aynı 500 örnekte logit farklarının dağılımına bakın, düşük güvenli tahminlerdeki (max prob < 0.6) hata oranını karşılaştırın. Ek: model sürümü uyuşmazlığı (eski artefakt paketlenmiş) — model hash'ini uygulama logundan doğrulayın.
