Bölüm 2: neden önemli, nasıl okunur

Kitabın en uzun ve en teknik bölümü (63 sayfa). Amacı model eğitmeyi öğretmek değil — yazar bunu açıkça söylüyor — hazır bir modeli seçerken ve kullanırken hangi özelliklerin ne anlama geldiğini göstermek. Bölümün sonunda şu üç soruya sayıyla cevap verebilmelisiniz: bu model neden bu kadar büyük, bu davranış nereden geliyor, aynı isteme neden farklı cevap alıyorum.

Ön koşul. F3'ün tamamı: transformer bloğu, tokenization, pretraining, SFT/DPO, sampling (temperature/top-p). F2'den FLOP ve bellek sezgisi. Bu bölüm bunları tekrar etmiyor; üstüne muhasebe katıyor: kaç parametre, kaç FLOP, kaç token, hangi dağılımdan örnek.

Parametre sayısı bir formüldür, sihir değil

Decoder-only bir transformer için parametreler üç kalemden gelir: gömme katmanı V⋅dV\cdot dV⋅d (kelime dağarcığı ×\times× model boyutu), konum gömmesi (öğrenilen ise Lmax⁡⋅dL_{\max}\cdot dLmax​⋅d), ve her katmanda dikkat + MLP + iki normalizasyon:

Nkatman=4d2+4d⏟Q,K,V,O+2 d dff+dff+d⏟MLP+4d⏟iki LayerNormN_{\text{katman}} = \underbrace{4d^2 + 4d}_{\text{Q,K,V,O}} + \underbrace{2\,d\,d_{ff} + d_{ff} + d}_{\text{MLP}} + \underbrace{4d}_{\text{iki LayerNorm}}Nkatman​=Q,K,V,O4d2+4d​​+MLP2ddff​+dff​+d​​+iki LayerNorm4d​​

GPT-2 small için d=768d=768d=768, dff=3072d_{ff}=3072dff​=3072, 12 katman, V=50,257V=50{,}257V=50,257, bağlam 1.024:

  • gömme: 50,257×768=38.650{,}257\times768 = 38.650,257×768=38.6M (toplamın ~%31'i!)
  • bir katman: 4d2+4d=2.364d^2+4d = 2.364d2+4d=2.36M, MLP =4.72= 4.72=4.72M, norm =0.003= 0.003=0.003M → 7.09M; 12 katman =85.1= 85.1=85.1M
  • toplam ≈124.4\approx 124.4≈124.4M — yayımlanan "124M" ile uyuşur.

İki ders: (i) küçük modellerde gömme tablosu baskındır (kelime dağarcığı büyükse), büyük modellerde ise katmanlar baskındır; (ii) ddd iki katına çıkınca katman maliyeti dört katına çıkar — bu yüzden "biraz daha büyük" model hiç de biraz değildir.

FLOP muhasebesi

Bir ileri geçişte her parametre bir çarpma-toplama görür; bir çarpma-toplama 2 FLOP sayılır. Yani token başına ileri geçiş ≈2N\approx 2N≈2N FLOP. Eğitimde geri yayılım ileri geçişin iki katıdır:

Feg˘itim≈(2N⏟ileri+4N⏟geri)×D=6NDF_{\text{eğitim}} \approx \left(\underbrace{2N}_{\text{ileri}} + \underbrace{4N}_{\text{geri}}\right) \times D = 6NDFeg˘​itim​≈​ileri2N​​+geri4N​​​×D=6ND

Burada 2N2N2N ve 4N4N4N token başına FLOP, DDD ise toplam token sayısıdır.

Çıkarım farkındalıklı ölçekleme

Modeli bir kez eğitip milyonlarca kez servis ediyorsunuz. Toplam maliyet eğitim + çıkarım:

Ctoplam=6ND+2N⋅SC_{\text{toplam}} = 6ND + 2N\cdot SCtoplam​=6ND+2N⋅S

SSS: ömür boyu servis edilen token sayısı. Aynı Lagrange adımı:

αAN−α=βBD−β⋅6D+2S6D=βBD−β(1+2S6D)\alpha A N^{-\alpha} = \beta B D^{-\beta}\cdot\frac{6D+2S}{6D} = \beta B D^{-\beta}\left(1+\frac{2S}{6D}\right)αAN−α=βBD−β⋅6D6D+2S​=βBD−β(1+6D2S​)

Sağ taraftaki çarpan 1'den büyüktür: NNN'yi artırmanın marjinal maliyeti 6D+2S6D+2S6D+2S iken DDD'yi artırmanınki 6N6N6N'dir; çıkarım terimi SSS büyüdükçe NNN pahalanır. Sonuç: çıkarım pahalıysa daha küçük model, daha çok veri. Llama 3 ailesinin 8B modelini ~15 trilyon token'la eğitmesi (token/parametre ~1.900) bu mantığın uç örneğidir (arXiv:2407.21783). Kitabın 2.2.2'de tartıştığı "ölçek büyüdükçe iyileşir mi" sorusunun mühendislik cevabı: büyüme sürüyor ama hangi eksende büyüdüğünüz artık maliyet fonksiyonunuza bağlı.

Üç iddiayı da sayıyla doğrulayan tek betik: parametre formülü (GPT-2 = 124M), Lagrange bölüşümü (analitik vs kaba kuvvet), sıcaklık/top-p/entropi ve çoğunluk oyunun Monte Carlo kontrolü.

# test: python 3.13 · numpy 2.5.4
# PC'de çalıştır — gerekli: numpy (CPU, < 2 sn)
# Bölüm 2'nin üç sonucunu doğrula:
# (1) parametre sayısı formülü, (2) hesap-optimal parametre/token bölüşümü,
# (3) sıcaklık / top-p örneklemesi ve kendi kendine tutarlılık (test-time compute).
import math
import numpy as np

# ---------- (1) parametre sayısı ----------
def gpt2_parametre(n_kat=12, d=768, d_ff=3072, V=50257, baglam=1024, bagli=True):
    gomme = V * d                       # token gömme (bağlıysa çıkış ağırlığı olarak da kullanılır)
    poz = baglam * d
    katman = n_kat * (4 * d * d + 4 * d + 2 * d * d_ff + d_ff + d + 4 * d)
    son_norm = 2 * d
    cikis = 0 if bagli else V * d       # bağlı gömmede ayrı çıkış katmanı yok
    return gomme + poz + katman + son_norm + cikis

print("GPT-2 small parametre (bağlı gömme):", f"{gpt2_parametre()/1e6:.1f}M",
      "| yayımlanan değer ~124M")
print("  gömme katmanı tek başına:", f"{50257*768/1e6:.1f}M")

# ---------- (2) Chinchilla bölüşümü ----------
A, B, alfa, beta = 406.4, 410.7, 0.34, 0.28   # yayımlanan uyum sabitleri

def kayip(N, D):
    return A / N**alfa + B / D**beta

def optimal(C):
    """6ND = C kısıtı altında analitik en iyi N, D (Lagrange koşulundan)."""
    # alfa*A*N^-alfa = beta*B*D^-beta  ve  6ND = C
    lo, hi = np.log(1e6), np.log(1e15)
    for _ in range(200):                        # N üzerinde ikili arama
        N = math.exp((lo + hi) / 2)
        D = C / (6 * N)
        sol = alfa * A * N**(-alfa)
        sag = beta * B * D**(-beta)
        if sol > sag:
            lo = (lo + hi) / 2
        else:
            hi = (lo + hi) / 2
    return N, C / (6 * N)

print("\nhesap C -> optimal N, D, token/parametre")
for C in (1e20, 1e21, 1e22, 1e23, 1e24):
    N, D = optimal(C)
    print(f"  C={C:5.0e}  N={N/1e9:7.2f}B  D={D/1e12:7.3f}T  D/N={D/N:6.1f}")

# kaba kuvvet doğrulama: N'yi tarayıp en küçük kaybı bul
C = 1e22
Ns = np.linspace(0.3e9, 30e9, 3000)
kayiplar = [kayip(n, C / (6 * n)) for n in Ns]
print(f"  kaba kuvvet en iyi N={Ns[int(np.argmin(kayiplar))]/1e9:.2f}B  (analitik {optimal(C)[0]/1e9:.2f}B)")

# ---------- (3) örnekleme ----------
logitler = np.array([2.0, 1.0, 0.5, -1.0])

def olasilik(z, T=1.0):
    z = z / T
    e = np.exp(z - z.max())
    return e / e.sum()

def entropi_bits(p):
    p = p[p > 0]
    return float(-(p * np.log2(p)).sum())

for T in (1.0, 0.5, 0.2):
    p = olasilik(logitler, T)
    print(f"T={T:3.1f}  p={np.round(p, 4)}  entropi={entropi_bits(p):.3f} bit")

p = olasilik(logitler, 1.0)
sira = np.argsort(-p)
kum = np.cumsum(p[sira])
k = int(np.searchsorted(kum, 0.9) + 1)
print(f"top-p=0.90 -> {k} token kalır: {sira[:k]}  yeniden normalize: {np.round(p[sira[:k]]/kum[k-1], 4)}")

# ---------- kendi kendine tutarlılık (çoğunluk oyu) ----------
def cogunluk_olasiligi(p, k):
    return sum(math.comb(k, i) * p**i * (1-p)**(k-i) for i in range(k//2+1, k+1))

print("\ntek örnek doğruluğu p -> k örnekte çoğunluk oyu doğruluğu")
print("   k:      1      3      5      9")
for p in (0.3, 0.4, 0.6, 0.8):
    print(f"  p={p:.1f}  " + "  ".join(f"{cogunluk_olasiligi(p, k):6.3f}" for k in (1, 3, 5, 9)))

rng = np.random.default_rng(0)
for p, k in [(0.4, 9), (0.8, 9)]:
    oy = (rng.random((200_000, k)) < p).sum(axis=1)
    print(f"  Monte Carlo p={p} k={k}: {np.mean(oy > k//2):.3f}  (analitik {cogunluk_olasiligi(p,k):.3f})")

Üç okuma:

  2. "20 token/parametre" sabit değil. Aynı fit, ölçekle birlikte 40'tan 98'e çıkıyor. Bir modele "compute-optimal" demek, hangi hesapta ve hangi çıkarım yükünde olduğunuzu söylemeden anlamsız.

Anlatım06 / 10

Pratik: tokenizer maliyeti, örnekleme taraması ve kendi bölüşümünüz

Kitapta numaralı alıştırma yok; bölümün alt başlıklarını ölçülebilir görevlere çeviriyoruz.

1. Tokenizer doğurganlığı (25 dk, 2.1.1). Aynı 20 cümleyi (10 Türkçe, 10 İngilizce) seçin. Kullandığınız sağlayıcının tokenizer'ıyla token sayın. Kelime başına token oranını ("doğurganlık") hesaplayın: Türkçe tipik olarak 1.6-2.4, İngilizce 1.2-1.4 aralığında çıkar. Sonra aynı içeriğin iki dilde maliyetini karşılaştırın. Çıktı: "Türkçe aynı bilgi için %X daha pahalı" cümlesi. Bu, çok dilli bir üründe fiyatlandırma kararınızı değiştirir.

2. Örnekleme taraması (25 dk, 2.4.2). 20 maddelik küçük bir görev seti alın (ör. tarih çıkarma). Üç koşu yapın: T=0.2T=0.2T=0.2, T=0.7T=0.7T=0.7, T=1.0T=1.0T=1.0 (top-p sabit 0.95). Her koşuda 3 örnek üretin ve şunları yazın: (i) doğruluk, (ii) aynı madde için 3 cevabın birbirinden farklı olma oranı, (iii) ortalama cevap uzunluğu. Beklenti: T=0.2T=0.2T=0.2'de fark oranı düşük ve doğruluk en yüksek; T=1.0T=1.0T=1.0'da fark oranı yükselirken doğruluk düşer. Fark oranı yüksek ama doğruluk aynıysa göreviniz "yetenek sınırında" değil, "ifade serbestliğinde" — değerlendirme setini tam eşleşmeden özellik kontrolüne çevirmelisiniz.

3. Kendi bölüşümünüz (20 dk, 2.2.2). Kod sayfasındaki optimal() fonksiyonunu kendi hesap bütçenizle çalıştırın (ör. 8×H100×30 gün → 8×30×24×3600×1.5×10148\times30\times24\times3600\times 1.5\times10^{14}8×30×24×3600×1.5×1014 FLOP). Çıkan NNN, DDD ile hedeflediğiniz açık modelin boyutunu karşılaştırın. Sonra çıkarım farkındalıklı versiyonu için: günlük istek ×\times× token ×\times× 365 ile SSS hesaplayın ve bölüşümün hangi yöne kaydığını yorumlayın.

Ek mini görev (teslim: yarım sayfa). Bir ürün senaryosu seçin ve sampling ayarlarını gerekçeyle sabitleyin: müşteri destek botu mu, yaratıcı yazım mı, JSON üreten bir ajan mı? Her biri için TTT, top-p, maksimum token ve "yeniden dene" politikası. Gerekçede entropi ve olasılıksal doğa dilini kullanın (ör. "aynı soruya iki farklı cevap kabul edilebilir, ama alan adı uydurulamaz → şema maskesi + T=0.3T=0.3T=0.3").

İpucu. Doğruluk ile çeşitlilik aynı anda ölçülmüyorsa hangi parametrenin ne yaptığını bilemezsiniz; tek değişkeni değiştirin (sıcaklık), diğerlerini sabitleyin.

Kontrol07 / 10

7B parametreli bir modeli 2 trilyon token ile eğitmenin hesap maliyeti nedir? Efektif 400 TFLOP/s varsayımıyla kaç GPU-günü eder?

Cevabı göster

FLOP ≈ 6ND = 6 × 7e9 × 2e12 = 8.4e22. Süre = 8.4e22 / 4e14 = 2.1e8 s ≈ 2.430 GPU-günü (yaklaşık 81 GPU-yılı). Not: 'efektif' kelimesi kritik; MFU %40 civarındaysa tepe FLOP'un 2.5 katı donanım gerekir, bu da maliyeti doğrudan 2.5 ile çarpar.

Kontrol08 / 10

Aynı isteme 8 örnek üretiyorsunuz, hepsi farklı çıkıyor. Bu bir hata mı? Üretim testinde ve değerlendirmede ne yapmalısınız?

Cevabı göster

Hata değil, beklenen davranış: 30-40 token'lık bir cevabın olasılığı token olasılıklarının çarpımı olduğu için (ör. 0.9^30 ≈ 0.04) tekrar olasılığı çok düşük. Testte tam eşleşme yerine özellik/değişmez kontrolü yazılır (şema geçerli mi, sayı doğru mu, yasak kelime yok mu). Değerlendirmede tek koşu değil k örnekli ortalama ve varyans raporlanır; karşılaştırmalı değerlendirmede aynı örnekler üzerinde eşleştirilmiş istatistik kullanılır. Determinizm gerekiyorsa T=0 + sabit seed, ama sağlayıcı tarafında batching nedeniyle tam determinizm garanti edilemez.

Kontrol09 / 10

Tek örnek doğruluğu 0.45 olan bir görevde 15 örnek alıp çoğunluk oyu kullanıyorsunuz. Beklenen doğruluk nedir? 45 örnekte ne olur, neden?

Cevabı göster

Çoğunluk oyu: P = Σ_{i>7.5} C(15,i)·0.45^i·0.55^(15-i) ≈ 0.346, yani tek örnekten kötü. 45 örnekte ≈ 0.249. Nedeni: çoğunluk oyu, tek örneğin yarıdan iyi olduğu varsayımına dayanır; p<0.5 iken örnek sayısı arttıkça yanlış çoğunluk daha güvenle seçilir. Ayrıca hatalar bağımsız değilse (aynı model, aynı istem) gerçek kazanç bu formülün altında kalır. Doğru hamle: önce p'yi 0.5'in üstüne çıkarmak (daha iyi istem, daha iyi model, CoT), sonra örnek çoğaltmak.

Özet10 / 10
  • Bölüm 2 modeli bir artefakt olarak anlatır: veri → mimari/boyut → post-training → örnekleme.
  • Parametre sayısı formülle hesaplanır: gömme VdVdVd + katman başına 4d2+2d dff4d^2+2d\,d_{ff}4d2+2ddff​; GPT-2 small = 124.4M, gömme tek başına 38.6M.
  • Eğitim maliyeti 6ND6ND6ND FLOP; 7B/2T ≈ 8.4e22 FLOP ≈ 2.430 GPU-günü (400 TFLOP/s efektif).
  • Lagrange koşulu αAN−α=βBD−β\alpha A N^{-\alpha} = \beta B D^{-\beta}αAN−α=βBD−β: parametre/veri bölüşümünün tamamı bu eşitlik. N∝Cβ/(α+β)N\propto C^{\beta/(\alpha+\beta)}N∝Cβ/(α+β), D∝Cα/(α+β)D\propto C^{\alpha/(\alpha+\beta)}D∝Cα/(α+β).
  • "20 token/parametre" bir kural değil, bir fitin küçük ölçek sonucu; aynı fit büyük hesapta 40-100 veriyor, yeniden üretim çalışmaları fitin güvenilmezliğini gösteriyor.
  • Çıkarım maliyeti hesaba girince optimum küçük model + çok veri yönüne kayar (Llama 3: 8B / 15T token).
  • Sıcaklık dağılımı keskinleştirir (T→0T\to0T→0 = argmax); top-k sabit, top-p uyarlanır destek. Entropi, rastgeleliğin ölçüsü.
  • Cevap olasılığı token olasılıklarının çarpımı: olasılıksal doğa test ve değerlendirme tasarımını belirler.
  • Çoğunluk oyu yalnız p>0.5p>0.5p>0.5 ve bağımsız hatalarda kazandırır; p=0.4p=0.4p=0.4, k=9k=9k=9 → 0.267.
