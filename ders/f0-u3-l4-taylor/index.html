Taylor yaklaşımı: yakından bakınca her eğri düzdür

Sezgi

Dünya yuvarlaktır ama bahçende düz görünür. Bir eğriyi yeterince büyütürsen (zoom) bir doğru gibi görünür. Bu doğru, o noktadaki teğet doğrudur: eğimi türevdir. Taylor yaklaşımı (Taylor expansion; bir fonksiyonu bir nokta çevresinde türevleri kullanarak basit bir polinomla taklit etme) bu fikrin resmi halidir.

Birinci derece: doğrusallaştırma

aaa noktası çevresinde:

f(a+h)≈f(a)+f′(a) hf(a + h) \approx f(a) + f'(a)\,hf(a+h)≈f(a)+f′(a)h

Okunuşu: "biraz ileri gidince değer = şimdiki değer + eğim × ne kadar gittiğin". Buna doğrusallaştırma (linearization; fonksiyonu bir nokta çevresinde teğet doğrusuyla değiştirme) denir. Türev dersinde yaptığımız "f(2.01)≈8.12f(2.01) \approx 8.12f(2.01)≈8.12" tahmini tam olarak buydu.

Elle: 4.1\sqrt{4.1}4.1​'i hesap makinesiz bul. f(x)=xf(x) = \sqrt{x}f(x)=x​, a=4a = 4a=4, h=0.1h = 0.1h=0.1. f′(x)=12xf'(x) = \frac{1}{2\sqrt{x}}f′(x)=2x​1​, yani f′(4)=14=0.25f'(4) = \frac{1}{4} = 0.25f′(4)=41​=0.25.

4.1≈2+0.25×0.1=2.025\sqrt{4.1} \approx 2 + 0.25 \times 0.1 = 2.0254.1​≈2+0.25×0.1=2.025

Çok değişkenli hali: gradyan ve Hessian bir arada

Birinci terim: şimdiki kayıp. İkinci: gradyanın söylediği eğim etkisi. Üçüncü: Hessian'ın söylediği eğrilik etkisi.

ML bağlantısı

  • Gradyanın tersine adım atmak, aslında birinci derece Taylor'a güvenmektir: "yakın çevrede kayıp doğrusal davranıyor". Bu güven yalnız küçük adımlarda geçerli; öğrenme oranının küçük olmasının matematiksel nedeni bu.
  • İkinci derece yaklaşımın minimumuna doğrudan atlamak Newton yöntemidir (U6'da).
  • Önceki dersteki "η<2/a\eta < 2/aη<2/a" sonucu, ikinci derece Taylor'ın tam doğru olduğu bir çanakta türetilmişti.

Sayısal türev ve gradyan kontrolü

İleri fark ve merkezi fark

Türevi bilgisayarda yaklaşık hesaplamanın iki yolu var:

I˙leri fark: f(x+h)−f(x)hMerkezi fark: f(x+h)−f(x−h)2h\text{İleri fark: } \frac{f(x + h) - f(x)}{h} \qquad \text{Merkezi fark: } \frac{f(x + h) - f(x - h)}{2h}I˙leri fark: hf(x+h)−f(x)​Merkezi fark: 2hf(x+h)−f(x−h)​

Hangisi daha iyi? Taylor'la bakalım.

Aynı hhh ile otuz kat daha iyi. Bu yüzden bütün kodlarımızda merkezi fark kullandık.

hhh'yi küçültmek her zaman iyi değil

Bilgisayar sayıları sonlu hassasiyetle tutar. float64 yaklaşık 16 anlamlı basamak taşır; en küçük göreli fark ε≈2.2×10−16\varepsilon \approx 2.2 \times 10^{-16}ε≈2.2×10−16 (makine epsilonu). hhh çok küçülünce f(x+h)f(x+h)f(x+h) ile f(x)f(x)f(x) neredeyse aynı sayı olur; çıkarınca anlamlı basamakların çoğu kaybolur (yuvarlama hatası). Sonra bunu küçük hhh'ye bölünce hata büyür.

İki hata birbirine karşı çalışır:

  • Kesme hatası (Taylor'da attığımız terimler): hhh küçüldükçe azalır.
  • Yuvarlama hatası: kabaca ε/h\varepsilon / hε/h, hhh küçüldükçe artar.

Pratik kural: ileri fark için h≈10−8h \approx 10^{-8}h≈10−8, merkezi fark için h≈10−5h \approx 10^{-5}h≈10−5 ile 10−610^{-6}10−6 civarı en iyisi. h=10−12h = 10^{-12}h=10−12 seçmek daha kötü sonuç verir. float32 (GPU'da sık kullanılır) ile bu sorun çok daha erken başlar; gradyan kontrolünü her zaman float64 ile yap.

Gradyan kontrolü (gradient checking)

Elle ya da yeni bir katman için türev yazdığında hata yapmak kolaydır ve model "bir şekilde" eğitilmeye devam ettiği için hata gözden kaçar. Gradyan kontrolü (gradient checking; analitik gradyanı sayısal gradyanla karşılaştırarak türev kodunu test etme) bunu yakalar. Ölçü olarak göreli hata kullanılır:

go¨reli hata=∥ganalitik−gsayısal∥∥ganalitik∥+∥gsayısal∥\text{göreli hata} = \frac{\|\mathbf{g}_{\text{analitik}} - \mathbf{g}_{\text{sayısal}}\|}{\|\mathbf{g}_{\text{analitik}}\| + \|\mathbf{g}_{\text{sayısal}}\|}go¨reli hata=∥ganalitik​∥+∥gsayısal​∥∥ganalitik​−gsayısal​∥​

Kabaca (float64, merkezi fark): 10−710^{-7}10−7'den küçük çok iyi; 10−410^{-4}10−4 civarı şüpheli; 10−210^{-2}10−2 ve üstü neredeyse kesin hata.

Tuzaklar

  • Kırık noktalar: ReLU x=0x = 0x=0'da kırılır (türevi yok). Tam kırığın yanında kontrol yaparsan sayısal fark iki tarafın ortalamasını verir ve yanlış alarm çalar.
  • Rastgelelik: dropout gibi rastgele katmanlar her çağrıda farklı sonuç verir; kontrolden önce kapat ya da tohum (seed) sabitle.
  • Maliyet: sayısal gradyan her parametre için 2 ileri geçiş ister. Milyonlarca parametrede eğitimde kullanılmaz; yalnız küçük modelde test için.
  • PyTorch'ta torch.autograd.gradcheck bu kontrolü hazır yapar (girdiler float64 olmalı).

Taylor yaklaşımlarını ve sayısal türev hatasının hhh ile değişimini görelim, sonra bir lojistik kayıp için gradyan kontrolü yapalım.

# test: python 3.13 · numpy 2.5.4
# PC'de çalıştır: pip install numpy scipy
import numpy as np

# 1) sqrt(4.1) için Taylor
a, h = 4.0, 0.1
t1 = np.sqrt(a) + 0.5 / np.sqrt(a) * h
t2 = t1 + 0.5 * (-0.25 * a**-1.5) * h**2
print(f"gerçek {np.sqrt(4.1):.8f}  1.derece {t1:.8f}  2.derece {t2:.8f}")
# gerçek 2.02484567  1.derece 2.02500000  2.derece 2.02484375

# 2) e^0.5 için terim ekledikçe
x = 0.5
terimler = [x**k / np.prod(range(1, k + 1)) for k in range(6)]   # x^k / k!
print(np.cumsum(terimler).round(5), round(np.exp(x), 5))
# [1.      1.5     1.625   1.64583 1.64844 1.6487 ] 1.64872

# 3) İleri vs merkezi fark: f = sin, x = 1, gerçek türev cos(1)
f, x0, gercek = np.sin, 1.0, np.cos(1.0)
for h in [1e-1, 1e-3, 1e-5, 1e-8, 1e-12]:
    ileri = (f(x0 + h) - f(x0)) / h
    merkez = (f(x0 + h) - f(x0 - h)) / (2 * h)
    print(f"h={h:.0e}  ileri hata={abs(ileri - gercek):.1e}  merkezi hata={abs(merkez - gercek):.1e}")
# h=1e-01  ileri hata=4.3e-02  merkezi hata=9.0e-04
# h=1e-03  ileri hata=4.2e-04  merkezi hata=9.0e-08
# h=1e-05  ileri hata=4.2e-06  merkezi hata=1.1e-11
# h=1e-08  ileri hata=1.4e-08  merkezi hata=3.0e-09
# h=1e-12  ileri hata=4.3e-05  merkezi hata=1.2e-05
# -> merkezi fark h=1e-5 civarında en iyi; h çok küçülünce yuvarlama hatası her şeyi bozuyor

# 4) Gradyan kontrolü: lojistik kayıp (ikili sınıflandırma kaybı, MLE dersinde türetilecek)
rng = np.random.default_rng(42)
X = rng.normal(size=(20, 3)); y = (rng.random(20) < 0.5).astype(float); w = rng.normal(size=3)
sig = lambda z: 1 / (1 + np.exp(-z))
def kayip(w):
    p = sig(X @ w)
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))
def grad_dogru(w):
    return X.T @ (sig(X @ w) - y) / len(y)
def grad_hatali(w):                       # sık hata: ortalama yerine toplam (1/n unutulmuş)
    return X.T @ (sig(X @ w) - y)

def sayisal_grad(f, w, h=1e-5):
    g = np.zeros_like(w)
    for i in range(len(w)):
        e = np.zeros_like(w); e[i] = h
        g[i] = (f(w + e) - f(w - e)) / (2 * h)
    return g

def goreli_hata(a, b):
    return np.linalg.norm(a - b) / (np.linalg.norm(a) + np.linalg.norm(b))

gs = sayisal_grad(kayip, w)
print(f"doğru gradyan : {goreli_hata(grad_dogru(w), gs):.1e}")    # doğru gradyan : 2.0e-11
print(f"hatalı gradyan: {goreli_hata(grad_hatali(w), gs):.1e}")   # hatalı gradyan: 9.0e-01

# Kütüphaneyle: NumPy, örneklenmiş verinin türevini merkezi farkla verir
xs = np.linspace(0, np.pi, 101)
print(np.abs(np.gradient(np.sin(xs), xs)[1:-1] - np.cos(xs)[1:-1]).max().round(6))   # 0.000164
