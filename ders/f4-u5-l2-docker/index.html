Anlatım01 / 12

"Benim makinemde çalışıyordu"

Model servisin laptopta çalışıyor. Sunucuya kopyalıyorsun: ModuleNotFoundError: No module named 'sklearn'. Kuruyorsun: sürüm farklı, predict_proba farklı davranıyor. Düzeltiyorsun: libgomp.so.1: cannot open shared object file — işletim sistemi farklı. Bu üç hata, tek bir sorunun belirtileri: çalıştırma ortamı, uygulamanın parçası değildi.

Konteyner (container) bu ortamı uygulamayla birlikte paketler: Python sürümü, kütüphane sürümleri, işletim sistemi kütüphaneleri, ortam değişkenleri. Sanal makineden farkı: çekirdeği paylaşır. İzolasyon iki Linux mekanizmasıyla sağlanır:

  • namespaces: süreç, ağ, dosya sistemi, kullanıcı görünümünü ayırır. Konteyner kendi PID 1'ini görür, kendi ağ arayüzünü görür.
  • cgroups: CPU, bellek, I/O üst sınırı koyar. --memory 1g dediğinde cgroup limitidir.

Bu yüzden konteyner saniyeler içinde açılır, VM gibi dakikalar değil: çekirdek yüklenmez.

Üç kelime: imaj, konteyner, registry

Kavram Nedir Benzetme
İmaj Salt okunur dosya sistemi katmanları + başlatma komutu Sınıf (class)
Konteyner İmajın çalışan örneği (+ yazılabilir üst katman) Nesne (instance)
Registry İmajların saklandığı depo (Docker Hub, GHCR, ECR) Paket deposu

docker run = imajdan konteyner yarat + komutu çalıştır. Aynı imajdan 5 konteyner çıkarabilirsin; her biri kendi yazılabilir katmanına yazar, imaj değişmez.

Docker bir derleme aracı değil, dağıtım aracıdır

Kritik zihniyet değişikliği: imaj, çalışan bir çıktıdır. İçinde kaynak kodun derlenmiş hâli, model dosyası, bağımlılıklar olur; git geçmişi, testler, not defterleri olmaz. "İmajı sunucuya girip pip install çalıştırırım" diyorsan konteynerin avantajını yok etmiş olursun: artık imaj tekrar üretilemez.

Bu yüzden soru "Docker'ı nasıl kurarım" değil, "bu imajı her seferinde aynı şekilde nasıl üretirim". Cevap: Dockerfile + sabitlenmiş sürümler + deterministik derleme.

Dockerfile neden "tarif" değil "program"

Dockerfile satır satır çalıştırılan bir programdır; her satır bir imaj katmanı üretir. Sırası önemlidir, çünkü Docker her katmanı derleme önbelleğine alır. Bir satır değişince o satır ve sonrasındaki tüm satırlar yeniden çalışır. Bu tek kural, aşağıdaki tüm pratiklerin gerekçesidir:

COPY . .                          # her kod değişikliğinde katman değişir
RUN pip install -r requirements.txt   # ... ve bağımlılıklar baştan kurulur

Sırayı çevir, 5 saniyelik derleme olur:

COPY requirements.txt .           # nadiren değişir
RUN pip install -r requirements.txt
COPY . .                          # sık değişir; yalnız bu katman yenilenir

İmaj boyutu ve güvenlik: sayıyla

Boyut nereden geliyor?

Ölçtüğümüz gerçek değerler (bu makinedeki site-packages, 1024 tabanlı MB):

Paket Boyut
scipy 81.2 MB
scikit-learn 37.5 MB
numpy 25.5 MB
pydantic_core 5.2 MB
joblib 1.9 MB
fastapi + starlette + uvicorn 1.7 MB
toplam (servis bağımlılıkları) ≈ 156 MB

Üç ders çıkıyor:

  1. Web çerçevesi bedava. FastAPI + uvicorn 2 MB bile değil. İmajı şişiren şey ML kütüphaneleri.
  2. scikit-learn kurunca scipy gelir. "Sadece sklearn kurdum" demek, 81 MB'lık bir bağımlılığı da aldım demektir. --no-deps ile atlamaya çalışmak kırılganlık üretir; doğrusu bilinçli kabul etmek.
  3. Testler ve .pyc dosyaları da gelir. scipy test dizinleri 17.8 MB, sklearn'ünkiler 6.4 MB — toplam 24 MB. Üretim imajında testlere ihtiyaç yok:
RUN find /usr/local/lib/python3.13/site-packages -type d -name tests -prune -exec rm -rf {} +

Bu satır imajı ~%15 küçültür. Tersi de doğru: bu satırı eklemek hata ayıklamayı zorlaştırır (bazı paketler tests içinden yardımcı modül import eder). Kendi bağlamında ölç, körü körüne ekleme.

Temel imaj seçimi

  • python:3.13 (tam) — Yaklaşık boyut: ~1 GB · Ne zaman: Derleme araçları gerekiyorsa (builder aşamasında)
  • python:3.13-slim — Yaklaşık boyut: ~130 MB · Ne zaman: Neredeyse her zaman; glibc uyumlu
  • python:3.13-alpine — Yaklaşık boyut: ~50 MB · Ne zaman: Küçük ama musl libc: numpy/scipy tekerlekleri (wheel) çoğu zaman yok, kaynaktan derleme gerekir
  • distroless — Yaklaşık boyut: ~50 MB · Ne zaman: Kabuk yok → saldırı yüzeyi küçük, hata ayıklama zor

ML servisleri için neredeyse her zaman doğru cevap slim. Alpine cazip görünür ama scipy'yi kaynaktan derlemek 20+ dakika ve 1 GB üstü geçici disk demektir.

Anlatım03 / 12

İmaj boyutu ve güvenlik: sayıyla (devam)

  1. Root olarak çalıştırma. USER appuser. Konteyner kaçarsa saldırganın elindeki yetki, root değil sıradan kullanıcı olur. Bazı kümeler (Pod Security Standards) root konteyneri reddeder.
  2. Katmana sır yazma. ENV API_KEY=... yazıp sonra RUN unset demek işe yaramaz: katman geçmişinde kalır, docker history ile okunur. Sırlar çalışma anında --env-file veya secret mount ile verilir.
  3. Sabit sürüm. Bağımlılık sabitleme: pip install scikit-learn yerine scikit-learn==1.9.1. Aksi hâlde altı ay sonra aynı Dockerfile farklı imaj üretir; "dün çalışıyordu" gizemi buradan çıkar. (requirements.txt'i pip-compile/uv lock ile kilitle.)

.dockerignore neden zorunlu

docker build . komutunda . bağlamdır (build context): Docker istemcisi bu dizini (varsayılan olarak) sunucuya gönderir. Proje kökünde 2 GB'lık .venv, data/, .git/ varsa her derlemede bunlar gönderilir. Yavaşlar, üstelik COPY . . ile imaja da girerler.

.dockerignore en azından şunları içermeli: .venv/, __pycache__/, *.pyc, .git/, data/, *.joblib (model builder'da üretiliyorsa), notebooks/, .env.

Çok aşamalı derleme

Çok aşamalı derleme (multi-stage build) iki ayrı imaj tanımlar: builder (derleme araçları, geçici dosyalar) ve runtime (yalnız çalışması için gerekenler). Runtime'a COPY --from=builder ile yalnız gerekli dosyalar geçer; derleyici, apt önbelleği, pip cache'i dışarıda kalır.

ML'de üçüncü bir faydası var: modeli builder aşamasında üretip runtime'a kopyalamak. Böylece konteyner açılırken eğitim yapılmaz — soğuk başlangıç kısalır ve aynı imaj her seferinde aynı modeli içerir.

# builder
RUN python -c "import servis_app; servis_app.egit_ve_kaydet()"
# runtime
COPY --from=builder /app/model.joblib .

Bu, "imaj = çıktı" ilkesinin somut hâli: model dosyası da imajın parçası, ayrı bir kopyalama adımı değil.

Kod04 / 12

Dockerfile'ı derlemeden denetleyen betik. Aşağıdaki iki Dockerfile üzerinde çalıştır: önce naif olan, sonra üretim olanı. Her ikisini Dockerfile adıyla kaydedip betiği çalıştır.

# PC'de çalıştır — yalnız standart kütüphane
# dockerfile_kontrol.py: Dockerfile'ı derlemeden denetler (hadolint'in küçük akrabası).
import re
import sys
from pathlib import Path

DOCKERFILE = Path("Dockerfile")


def oku(yol):
    """Satır birleştirmelerini (sondaki ters bölü ile devam) tek talimata indirger."""
    talimatlar, tampon = [], ""
    for satir in yol.read_text().splitlines():
        if satir.strip().startswith("#") or not satir.strip():
            continue
        tampon += satir.rstrip("\\").strip() + " "
        if not satir.rstrip().endswith("\\"):
            talimatlar.append(tampon.strip())
            tampon = ""
    return talimatlar


talimatlar = oku(DOCKERFILE)
froms = [t for t in talimatlar if t.upper().startswith("FROM ")]
sonuclar = []


def kontrol(ad, kosul, ayrinti):
    sonuclar.append((ad, bool(kosul), ayrinti))


etiketler = [f.split()[1] for f in froms]
kontrol("base imaj etiketli", all(":" in e and not e.endswith(":latest") for e in etiketler),
        f"FROM: {', '.join(etiketler)}")

kaynaklar = [t.split()[1] for t in talimatlar if t.upper().startswith("COPY --FROM=")]
kontrol("çok aşamalı derleme", len(froms) >= 2 and kaynaklar,
        f"{len(froms)} aşama, COPY --from: {kaynaklar}")

pip_satirlari = [t for t in talimatlar if "pip install" in t]
kontrol("pip --no-cache-dir", pip_satirlari and all("--no-cache-dir" in t for t in pip_satirlari),
        f"{len(pip_satirlari)} pip install satırı")

sira = [i for i, t in enumerate(talimatlar) if re.match(r"COPY .*requirements\.txt", t)]
kod = [i for i, t in enumerate(talimatlar) if re.match(r"COPY (?!--from).*\.py", t)]
kontrol("önce requirements, sonra kod", bool(sira and kod) and max(sira) < min(kod),
        f"requirements@{sira}, kod@{kod}")

kullanicilar = [t.split()[1] for t in talimatlar if t.upper().startswith("USER ")]
kontrol("root olmayan USER", kullanicilar and kullanicilar[-1] not in ("root", "0"),
        f"USER {kullanicilar}")

cmd = [t for t in talimatlar if t.upper().startswith("CMD ")]
kontrol("CMD exec biçimi", cmd and cmd[-1].strip().upper().startswith("CMD ["),
        cmd[-1][:60] if cmd else "yok")

kontrol("HEALTHCHECK", any(t.upper().startswith("HEALTHCHECK") for t in talimatlar),
        "docker ps'te sağlık durumu görünür")

supheli = [t for t in talimatlar if t.upper().startswith(("ENV ", "ARG "))
           and re.search(r"(KEY|TOKEN|SECRET|PASSWORD|PASSWD)", t.upper())]
kontrol("katmanda sır yok", not supheli, f"şüpheli: {supheli}" if supheli else "temiz")

di = Path(".dockerignore")
icerik = di.read_text() if di.exists() else ""
kontrol(".dockerignore", di.exists() and ".venv" in icerik, icerik.replace("\n", " ")[:70])


def boyut(yol):
    if yol.is_file():
        return yol.stat().st_size
    return sum(f.stat().st_size for f in yol.rglob("*") if f.is_file())


toplam = boyut(Path("."))
venv = boyut(Path(".venv")) if Path(".venv").exists() else 0
kontrol("bağlam bildirimi", True, f"toplam {toplam / 1e6:.1f} MB, .venv {venv / 1e6:.1f} MB")

for ad, ok, ayrinti in sonuclar:
    print(f"{'GEÇTİ' if ok else 'KALDI':<6} {ad:<28} {ayrinti}")
sys.exit(0 if all(ok for _, ok, _ in sonuclar) else 1)

Kod05 / 12

Üretim Dockerfile'ı, requirements.txt, .dockerignore ve derleme/çalıştırma komutları. Not: bu dersin yazıldığı ortamda imaj kayıt defterine (registry) ağ erişimi yoktu; imaj derlenmedi, aşağıdaki sayılar senin makinende ölçülmeli. Dockerfile sözdizimi ve mantığı yukarıdaki denetleyiciyle doğrulandı.

# ---- aşama 1: bağımlılıklar ve model ----
FROM python:3.13-slim AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt
ENV PYTHONPATH=/install/lib/python3.13/site-packages
COPY servis_app.py .
RUN python -c "import servis_app; servis_app.egit_ve_kaydet()"

# ---- aşama 2: çalışma imajı ----
FROM python:3.13-slim AS runtime
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 PORT=8000
WORKDIR /app
COPY --from=builder /install /usr/local
COPY --from=builder /app/model.joblib .
COPY servis_app.py .
RUN useradd --create-home --uid 10001 appuser && chown -R appuser:appuser /app
USER appuser
EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health', timeout=2)"
CMD ["uvicorn", "servis_app:app", "--host", "0.0.0.0", "--port", "8000"]
# requirements.txt — sürümler sabit
fastapi==0.115.6
uvicorn[standard]==0.34.0
scikit-learn==1.6.0
joblib==1.4.2
numpy==2.2.1
# .dockerignore
__pycache__/
*.pyc
.venv/
.git/
data/
model.joblib
*.ipynb
.env
docker build -t titanic-servis:0.1 .
docker images titanic-servis                 # boyutu not et
docker run -d --name api -p 8000:8000 titanic-servis:0.1
docker ps                                    # STATUS: Up ... (healthy)
curl -s localhost:8000/health                # {"status":"ok"}
curl -s -X POST localhost:8000/predict -H 'content-type: application/json' \
  -d "$(python -c 'import json;from sklearn.datasets import load_breast_cancer as l;print(json.dumps({"features":l().data[0].tolist()}))')"
docker exec api whoami                       # appuser (root değil)
docker history titanic-servis:0.1            # katmanlar; sır aramak için
docker stop api && docker rm api

Kontrol listesi (senin makinende doğrula):

  1. docker images boyutu ≈ temel imaj (130 MB) + site-packages (156 MB) + kod. 300 MB civarı beklenir.
  2. Kodda tek satır değiştir (ör. SURUM), tekrar derle: pip katmanı CACHED gelmeli, süre saniyeler olmalı. requirements.txt'e bir paket ekle: pip katmanı ve sonrası yeniden çalışır.
  3. docker run --memory 256m ile başlat: OOMKilled görürsün — limitin gerçekten uygulandığının kanıtı.
  4. docker exec api whoami → appuser. docker history çıktısında API anahtarı olmamalı.
Anlatım06 / 12

Pratik: servisi imaja çevir, küçült, ölç

Görev. U5-L1'deki FastAPI servisini üretim kalitesinde bir imaja paketle. Üç ölçüm yap ve not et.

  1. Naif imaj: FROM python, COPY . ., RUN pip install ..., root kullanıcı. Derle, boyutunu ve derleme süresini yaz.
  2. Üretim imajı: bu dersteki çok aşamalı Dockerfile. Derle, aynı ölçümleri yap. dockerfile_kontrol.py ile 10/10 geçtiğini doğrula.
  3. Önbellek deneyi: üretim imajında servis_app.py içinde SURUM değerini değiştir ve yeniden derle. Süreyi ölç. Sonra requirements.txt'e httpx ekle ve yeniden derle. İki süreyi karşılaştır — fark, katman sırasının değeridir.
  4. Çalıştır ve doğrula: docker run -d -p 8000:8000, /health 200, /predict gerçek olasılık, docker exec api whoami → appuser. docker stop sonrası docker ps -a çıktısında çıkış kodunu gör (143 = SIGTERM).
  5. Küçültme deneyi: runtime aşamasına RUN find ... -name tests -prune -exec rm -rf {} + ekle, boyutu tekrar ölç. Kazancı MB olarak yaz; python -c "import sklearn; sklearn.__version__" hâlâ çalışıyor mu kontrol et.

Beklenen sonuç. Naif imaj tipik olarak üretim imajından belirgin büyük (tam python temeli + .venv/data kopyası). Önbellek deneyinde kod değişikliği ~1-3 saniyede, bağımlılık değişikliği dakikalarda derlenir. Test dizinlerini silmek ~24 MB kazandırır.

İpucu. Derleme süresini time docker build ... ile ölç. docker history --no-trunc katman katman boyut gösterir; en büyük katman genelde pip install. İmaj boyutunu küçültmenin en etkili yolu satır silmek değil, temel imajı ve bağımlılık listesini küçültmektir.

Ek pratik. Aynı servisi python:3.13-alpine ile derlemeyi dene ve neden başarısız olduğunu (veya ne kadar sürdüğünü) yaz: numpy/scipy için musl uyumlu wheel bulunmazsa kaynaktan derleme başlar. Bu deney, "küçük imaj her zaman iyi mi" sorusunun cevabını verir.

Kontrol07 / 12

Dockerfile'da COPY . . satırını RUN pip install -r requirements.txt satırının üstüne koydun. Kodda tek karakter değiştirdiğinde ne olur, neden?

Cevabı göster

COPY . . katmanı değişir; Docker katman önbelleğini o noktadan sonra geçersiz sayar, dolayısıyla pip install her derlemede baştan çalışır: saniyeler yerine dakikalar. Çözüm: önce yalnız requirements.txt'i kopyala, kur, sonra kaynak kodu kopyala — bağımlılık katmanı kod değişikliklerinden etkilenmez.

Kontrol08 / 12

İmajda ENV DB_PASSWORD=hunter2 yazıp hemen ardından RUN unset DB_PASSWORD çalıştırdın. Sır güvende mi?

Cevabı göster

Hayır. Her RUN ayrı bir katmandır; ENV katmanında değer durur, unset yalnız sonraki katmanın ortamını temizler. docker history --no-trunc veya imajı çıkaran herkes değeri okuyabilir. Sırlar çalışma anında verilmeli: --env-file, Docker/Kubernetes secret, Vault gibi harici store. Ayrıca sır enjekte edilmiş imajı registry'ye itmek sızıntıyı kalıcılaştırır.

Kontrol09 / 12

İmaj 320 MB, bunun 156 MB'ı site-packages. scipyyi --no-deps ile atlarsan imaj 240 MB olur. Neden bu genelde kötü bir fikir?

Cevabı göster

scikit-learn scipy'yi gerçekten kullanır (bazı lineer cebir/optimizasyon yolları, scipy.sparse, dağılımlar); --no-deps ile atlamak import veya çalışma anında ModuleNotFoundError/yanlış davranış üretir, testlerde yakalanmazsa üretimde patlar. Doğru yaklaşım: bağımlılığı kabul et, boyutu temel imaj seçimi, test/.pyc temizliği ve gereksiz paketleri (ör. pandas kullanılmıyorsa) çıkarmakla düşür. Boyut hedefi bir bütçedir; kırılganlıkla satın alınmaz.

Soru10 / 12

Aynı FastAPI + scikit-learn servisi için python:3.13-alpine (~50 MB) ile python:3.13-slim (~130 MB) arasında seçim yapıyorsun. Alpine neden ML servisinde genelde kötü tercih?

Seçenekler

İmaj boyutunu taban imaj değil bağımlılıklar belirler: scipy ~81 MB, scikit-learn ~37 MB, numpy ~25 MB. slim glibc uyumludur ve tekerlekler hazırdır; alpine'de numpy ve scipy artık musllinux_1_2 wheel'i yayınlasa da scikit-learn yayınlamaz, pip sdist derlemesine düşer ve derleyici kurulmadan kurulum hemen hata verir; kazanç tersine döner.

Soru11 / 12

Çok aşamalı derlemede builder aşaması 2,1 GB yer kaplıyor. Runtime aşaması python:3.13-slim (130 MB) + kopyalanan site-packages (156 MB) + kod ve model (4 MB). Son imaj yaklaşık kaç MB?

Yalnız COPY --from=builder ile seçilen dosyalar geçer: 130+156+4=290130 + 156 + 4 = 290130+156+4=290 MB. Builder'daki derleyici, apt ve pip cache'i son imaja girmez; çok aşamalı derleme tam olarak bu farkı üretir.

Özet12 / 12
  • Konteyner = izole süreç (namespaces) + kaynak sınırı (cgroups) + imajdan gelen dosya sistemi. VM'den farkı çekirdeği paylaşması.
  • İmaj salt okunur katmanlardan oluşur; konteyner imajın çalışan örneğidir. Registry imaj deposudur.
  • Dockerfile bir programdır: her satır katman, her katman önbelleklenir. Nadiren değişen üste, sık değişen alta.
  • Boyut ML kütüphanelerinden gelir: ölçtüğümüzde scipy 81 MB, sklearn 37.5 MB, numpy 25.5 MB; toplam 156 MB. Test dizinleri 24 MB.
  • Temel imaj: ML için slim; alpine musl yüzünden kaynaktan derleme tuzağı.
  • Çok aşamalı derleme derleyici/pip cache'i dışarıda bırakır; ML'de ek olarak modeli builder'da üretip runtime'a kopyalar (deterministik, hızlı soğuk başlangıç).
  • Güvenlik: USER root değil, katmanda sır yok, sürümler sabit, .dockerignore bağlamı küçültür.
  • Dockerfile'ı CI'da statik denetlemek (base etiketi, USER, HEALTHCHECK, katman sırası) ucuz ve etkili bir kapıdır.
